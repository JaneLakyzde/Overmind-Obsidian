一种简单但非常有效的集成方法，核心思想是**用完全相同的数据集训练多个不同类型的基础模型，再用“投票”机制综合它们的判断**

- **本质**：不直接降低偏差或方差，而是通过模型多样性“取长补短”提升稳健性
    
- **优势**：即使各个模型在某些样本上犯错，只要它们犯的错不重叠，投票就能相互纠正
    
- **关键区别**：Bagging/Boosting 通过数据扰动提升单模型的多样性；投票分类器则是依靠**算法层面的异质性**
    

# 硬投票

**机制**：每个模型输出一个类别标签，取多数票为最终结果。原理非常直白：

|模型|预测结果|
|---|---|
|逻辑回归|✅ A类|
|SVM|✅ A类|
|决策树|B类|
硬投票 → A类（2票 vs 1票）

- **适用场景**：当所有模型的准确率大致相当时，简单多数投票最公平、最不易引入偏差
    
- **局限**：硬投票把“99%确定”和“51%确定”的预测看成同等的一票，丢失了置信度信息
    

# 软投票

**机制**：每个模型输出概率（或置信度），取所有概率的平均值，选平均概率最高的类别

| 模型     | 预测为 A 类的概率                         | 预测为 B 类的概率                         |
| ------ | ---------------------------------- | ---------------------------------- |
| 逻辑回归   | 0.80                               | 0.20                               |
| SVM    | 0.70                               | 0.30                               |
| 决策树    | 0.40                               | 0.60                               |
| **平均** | **(0.80+0.70+0.40)/3  <br>= 0.63** | **(0.20+0.30+0.60)/3  <br>= 0.37** |
软投票 → A类（0.63 > 0.37）


- **关键前提**：基模型必须支持 `predict_proba()`（SVM 需设置 `probability=True`）
    
- **为什么通常更优**：高置信度预测自然拥有更大影响力，而含糊预测对结果影响越小，相当于隐式的“动态加权”
    
- **额外做法**：也可用中位数代替平均值，在存在极端预测值时更稳健[](https://www.baeldung-cn.com/cs/hard-vs-soft-voting-classifiers)
    

# 加权投票

**机制**：为不同模型手动设定不同权重，模型越可靠 → 权重越大 → 在投票中越有话语权

|模型|准确率|预设权重|对 A 类的概率|
|---|---|---|---|
|XGBoost|95%|3|0.90 × 3 = 2.70|
|随机森林|87%|1|0.60 × 1 = 0.60|
|逻辑回归|80%|1|0.40 × 1 = 0.40|
|**加权平均**|||**(2.70+0.60+0.40)/(3+1+1) = 0.74**|

即使两个模型“反对”，表现最好的模型因其高权重仍能主导最终结果[](https://developer.volcengine.com/articles/7451506263474569252)。将硬投票、软投票、加权投票的计算方式放在一起对比会更直观：

|投票方式|输入|组合方法|输出|
|---|---|---|---|
|**硬投票**|类别标签（0/1）|多数票|最终类别|
|**软投票**|类别概率|平均概率|最终类别|
|**加权软投票**|类别概率|加权平均概率|最终类别|

# 偏差-方差视角

**投票分类器主要降低方差，但不直接降低偏差。**

- 每个基础模型都是在**同一个完整数据集**上训练的（对比 Bagging 通过数据子集制造多样性）。不同模型从不同假设空间“审视”同一数据时，不太容易在同一处犯完全相同的错误——集成后这些个别偏差被相互稀释，方差降低，整体预测更加稳健[](https://blog.csdn.net/dataschool/article/details/141182014)。
    
- 与之对比：Boosting 通过利用错误样本来降偏差，Bagging 利用随机抽样来降方差。
    

# **对比 [[Bagging]]**

投票分类器在“聚合阶段”和Bagging用了同样的方式（投票/平均），但它在最关键的“生成模型多样性”这一步走了完全不同的路。

- **Bagging的多样性**：来自**数据扰动**。同一个算法，喂不同的数据子集，生成多个有差异的模型来降方差。
    
- **投票分类器的多样性**：来自**算法扰动**。同一份完整数据，丢给逻辑回归、SVM、决策树等完全不同的算法，让它们互相取长补短。
    

所以，虽然它和Bagging一样是并行训练、用投票来聚合，但它**缺少了Bagging的标志性动作——自助法重采样（Bootstrap）**。通常我们把它归为“并行集成”这个大类下的一个独立子类，而不是算作Bagging的一步。

|对比维度|**投票分类器**|**Bagging（装袋）**|
|---|---|---|
|**数据**|所有模型共用**同一份完整数据**|每个模型用**不同的Bootstrap子集**（有放回抽样）|
|**算法**|**必用不同算法**（异质，如SVM+RF+KNN）|**必用相同算法**（同质，如都是决策树）|
|**多样性来源**|算法的“认知差异”|数据的“视角差异”|
|**核心目标**|取长补短，综合异质模型优势|降低方差，抑制同质复杂模型过拟合|
|**投票方式**|硬/软投票都常用，软投票更佳|分类多用硬投票，回归用平均|
# Scikit-learn 实现

**关键参数**（`from sklearn.ensemble import VotingClassifier`）

|参数|说明|默认值|
|---|---|---|
|`estimators`|列表，元素为 `(名称, 模型对象)` 元组|必填|
|`voting`|策略：`'hard'`（多数票）或 `'soft'`（概率平均）|`'hard'`|
|`weights`|列表，对应各模型的权重|全部为 1（均匀）|
|`n_jobs`|并行训练线程数，`-1` 表示全用|`1`|
|`flatten_transform`|仅对软投票生效，控制 `transform()` 的输出形状|`True`|

> **注意**：软投票时 SVM 必须加 `probability=True`；GridSearch 调整基模型参数时用 `estimator_name__parameter` 双下划线格式
