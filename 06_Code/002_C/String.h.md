
# C风格字符串 (C-Style Strings) 

这份笔记旨在从底层原理到实战应用，全面解析 **C风格字符串（C-Style Strings）**。作为一个ACM选手，掌握它是理解内存管理和算法优化的基石，尽管现代C++推荐使用 `std::string`，但在底层交互、嵌入式开发及部分算法题中，`char` 数组依然无处不在。
## 1. 内存本质 (Memory Essence)

C风格字符串在本质上是**以空字符 `\0` (Null Terminator) 结尾的字符数组**。

- **连续内存：** 字符在内存中是连续存放的。
    
- **哨兵机制：** 计算机并不存储字符串的长度，而是依赖末尾的 `\0` (ASCII值为0) 来标记结束。如果丢失了这个哨兵，程序会越界读取，导致乱码或段错误 (Segmentation Fault)。
    
- **指针退化：** 数组名在大多数表达式中会退化为指向首元素的指针 (`char*`)。
    

$$\text{Size needed} = \text{Length of string} + 1$$

> **ACM 提示：** 在定义数组大小时，永远不要吝啬那一个字节。如果题目要求字符串长度为 $N$，请至少开 $N+1$，甚至 $N+5$ 以防万一。

## 2. 常用头文件

- **C 语言环境：**
    
    - `<string.h>`: 提供处理字符串的核心函数（如 `strcpy`, `strlen`）。
        
    - `<ctype.h>`: 提供字符处理函数（如 `isalpha`, `isdigit`, `toupper`）。
        
- **C++ 环境：**
    
    - `<cstring>`: 对应 C 的 string.h。
        
    - `<cctype>`: 对应 C 的 ctype.h。

## 3. 定义与初始化

### 3.1 栈上数组 (Stack Array)

这是最常见且安全的方式，内存可读写。

C++

```
// 方式 A: 自动推导长度 (包含 \0，大小为6)
char str1[] = "Hello"; 

// 方式 B: 指定大小 (推荐，尤其在全局变量区)
char str2[100] = "World"; 

// 方式 C: 逐个赋值 (极易出错，容易漏掉 \0)
char str3[6] = {'H', 'e', 'l', 'l', 'o', '\0'}; 
```

### 3.2 字符串字面量指针 (String Literal Pointer)

**⚠️ 高危操作：**

C++

```
const char* str = "Hello"; // 推荐加上 const
// str[0] = 'h'; // 运行时错误 (Runtime Error)！
```

- **原因：** `"Hello"` 存储在**只读数据段 (Text/Data Segment)**。试图修改它会导致操作系统抛出写入异常。在ACM比赛中，这会导致 RE。

## 4. 输入与输出

### 4.1 输出

- `printf("%s", str);`: 高效，C语言标准。
    
- `cout << str;`: C++ 方式，自动识别 `\0` 停止。
    

### 4.2 输入 (难点与坑点)

|**函数/方法**|**特性**|**安全性**|**遇到空格/换行**|**备注**|
|---|---|---|---|---|
|`scanf("%s", str)`|基础|**低** (易溢出)|停止读取|无法读入带空格的句子|
|`cin >> str`|C++流|**低** (易溢出)|停止读取|同上|
|`gets(str)`|**已废弃**|**极低**|读入空格，换行停止|**C11/C++14已移除，严禁使用**|
|`fgets(buf, n, stdin)`|C标准|**高**|读入空格，保留换行符|最安全的C函数|
|`cin.getline(s, n)`|C++流|**高**|读入空格，丢弃换行符|处理 char 数组的首选|

### 4.3 详解 cin.getline 与 cin.ignore

在处理混合输入（先读数字，再读字符串）时，缓冲区残留的换行符是最大隐患。

**场景复现：**

C++

```
int n;
char str[100];

cin >> n; // 输入 "10\n"
// cin 读取了 10，但 '\n' 留在了缓冲区
cin.getline(str, 100); // 发现缓冲区第一个就是 '\n'，直接结束，str 为空串
```

**解决方案：使用 `cin.ignore()`**

C++

```
cin >> n;
cin.ignore(); // 默认忽略1个字符，通常是吞掉那个 '\n'
// 或者更稳健的写法：
// cin.ignore(numeric_limits<streamsize>::max(), '\n'); 
cin.getline(str, 100); // 此时能正常读入
```

## 5. 核心操作函数 (string.h / cstring)

这些函数都依赖 `\0` 来确定边界，时间复杂度通常为 $O(N)$。

| **函数**   | **原型示例**                         | **功能描述**         | **注意事项**                              |
| -------- | -------------------------------- | ---------------- | ------------------------------------- |
| `strlen` | `size_t strlen(const char* s)`   | 返回字符串长度而非大小      | **不包含** `\0`;而`sizeof` = `strlen` + 1 |
| `strcpy` | `char* strcpy(dest, src)`        | 将 src 复制到 dest   | dest 空间必须足够大                          |
| `strcat` | `char* strcat(dest, src)`        | 将 src 拼接到 dest 后 | dest 必须有足够空间容纳两者                      |
| `strcmp` | `int strcmp(s1, s2)`             | 比较字典序            | s1 < s2 返回负数, = 返回 0, > 返回正数          |
| `strstr` | `char* strstr(haystack, needle)` | 查找子串             | 返回第一次出现位置的指针，未找到返 NULL                |

> **ACM 技巧：** `strlen` 的时间复杂度是 $O(N)$。**不要**把它写在循环条件里！
> 
> 错误写法： for(int i=0; i < strlen(s); i++) { ... } (导致复杂度变 $O(N^2)$)
> 
> 正确写法： int len = strlen(s); for(int i=0; i < len; i++) { ... }
> // 结果：6 (包含末尾隐藏的 \0) // "Hello" 在内存中是 'H','e','l','l','o','\0' cout << sizeof("Hello") << endl;

## 6. 与 C++ std::string 的区别

|**特性**|**C 风格字符串 (char*)**|**C++ std::string**|
|---|---|---|
|**内存管理**|手动管理，静态大小或 `malloc`|自动管理，动态扩容|
|**安全性**|易发生缓冲区溢出|安全，越界有检查 (at)|
|**赋值/拼接**|`strcpy`, `strcat`|`=`, `+`, `+=` (直观)|
|**比较**|`strcmp(a, b) == 0`|`a == b`|
|**结尾**|必须有 `\0`|不依赖 `\0` (记录 size)|
|**效率**|极高 (无额外开销)|略低 (有堆内存分配开销)|
|**转换**|原生支持|需调用 `.c_str()` 转为 C 风格|

## 7. 总结与建议

1. **首选 `std::string`：** 在现代 C++ 开发和大多数 ACM 题目中，除非受限于内存极其严苛或需要与底层 C API 交互，否则优先使用 `std::string`。
    
2. **警惕越界：** 操作 `char` 数组时，心中永远要有内存布局图，确保 `\0` 有位置安放。
    
3. **IO 匹配：** `scanf/printf` 配合 C 串效率极高；若混用 `cin/cout`，务必注意 `sync_with_stdio(0)` 和缓冲区残留问题。
