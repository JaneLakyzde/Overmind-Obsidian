下面从**语言语义 + 存储期 + 作用域 + 链接属性 + 实现层面**五个维度，系统性地说明 **C++ 中全局变量、静态变量、常量（`const` / `constexpr`）等不同类型的区别**，并解释它们在编译器与链接阶段是如何实现的。

---

## 一、核心分类总览（先给你一张“地图”）

| 声明方式           | 存储期   | 作用域   | 链接属性       | 是否可修改 | 典型用途     |
| -------------- | ----- | ----- | ---------- | ----- | -------- |
| 普通全局变量         | 静态存储期 | 全局    | 外部链接       | ✔     | 跨文件共享状态  |
| `static` 全局变量  | 静态存储期 | 文件内   | 内部链接       | ✔     | 文件私有全局状态 |
| 局部变量           | 自动存储期 | 块内    | 无          | ✔     | 普通局部数据   |
| `static` 局部变量  | 静态存储期 | 块内    | 无          | ✔     | 函数内持久状态  |
| `const` 全局变量   | 静态存储期 | 全局    | **默认内部链接** | ✘     | 常量配置     |
| `extern const` | 静态存储期 | 全局    | 外部链接       | ✘     | 跨文件常量    |
| `constexpr`    | 静态存储期 | 取决于位置 | 默认内部链接     | ✘     | 编译期常量    |
| 类内 `static` 成员 | 静态存储期 | 类作用域  | 外部链接       | 视情况   | 类级共享数据   |

## 二、存储期（Lifetime）：变量活多久？

### 1️⃣ 静态存储期（Static Storage Duration）

**程序启动时分配，程序结束时释放**

包括：

- 所有全局变量
    
- 所有 `static` 变量（无论在全局还是函数内）
    
- 所有命名空间作用域的 `const` / `constexpr`
    

```cpp
int g;              // 静态存储期
static int sg;      // 静态存储期
void f() {
    static int x;   // 静态存储期
}
```

👉 **本质实现**：  
编译器把它们放入 **`.data` / `.bss` / `.rodata` 段**。

---

### 2️⃣ 自动存储期（Automatic Storage Duration）

**进入作用域创建，离开作用域销毁**

```cpp
void f() {
    int x = 10; // 自动存储期（栈）
}
```

👉 **本质实现**：  
通常分配在 **栈（stack）** 上。

---

## 三、作用域（Scope）：在哪能“看到”它？

### 1️⃣ 全局作用域

```cpp
int g;
```

- 在声明点之后，整个翻译单元可见
    

---

### 2️⃣ 文件作用域（通过 `static`）

```cpp
static int file_only;
```

- 只在 **当前 `.cpp` 文件** 内可见
    
- 不会被其他文件 `extern` 到
    

---

### 3️⃣ 块作用域

```cpp
void f() {
    int x;
    static int y;
}
```

- `x`：普通局部变量
    
- `y`：**只初始化一次，但只在函数内可见**
    

---

## 四、链接属性（Linkage）：能不能跨文件？

这是 C++ 中**最容易混淆、但最重要的区别**。

---

### 1️⃣ 外部链接（External Linkage）

> **多个翻译单元可以指向同一个实体**

```cpp
// a.cpp
int g = 10;

// b.cpp
extern int g;
```

- 链接器会把 `g` 解析为同一个符号
    

---

### 2️⃣ 内部链接（Internal Linkage）

> **每个翻译单元一份**

```cpp
// a.cpp
static int x = 1;

// b.cpp
static int x = 2;
```

- 两个 `x` 完全无关
    
- 链接器看不到对方的符号
    

---

### 3️⃣ 关键点：`const` 的“反直觉行为”

```cpp
// header.h
const int N = 10;
```

**默认是：内部链接！**

- 每个包含该头文件的 `.cpp` 都有一份 `N`
    
- 不会产生 ODR 冲突
    

👉 如果你要跨文件共享：

```cpp
// header.h
extern const int N;

// source.cpp
const int N = 10;
```

---

## 五、常量体系：`const` vs `constexpr`

### 1️⃣ `const`

- **语义**：只读
    
- **不保证编译期可知**
    

```cpp
const int x = foo(); // 合法（运行期）
```

---

### 2️⃣ `constexpr`

- **语义**：必须是编译期常量
    
- 可以参与模板、数组大小、`case` 标签等
    

```cpp
constexpr int N = 10;
int arr[N]; // OK
```

#### 链接属性

- 命名空间作用域：**内部链接**
    
- 类内 `static constexpr`：可不单独定义（C++17 起）
    

---

## 六、`static` 的三种完全不同含义（非常重要）

### 1️⃣ `static` + 全局变量

```cpp
static int g;
```

➡ **内部链接**（文件私有）

---

### 2️⃣ `static` + 局部变量

```cpp
void f() {
    static int x;
}
```

➡ **延长生命周期，不改变作用域**

---

### 3️⃣ `static` + 类成员

```cpp
struct A {
    static int x;
};
```

➡ **属于类，而不是对象**

```cpp
int A::x = 10;
```

---

## 七、从“实现角度”看（编译器/链接器做了什么）

### 1️⃣ 编译阶段

- 决定：
    
    - 存储期
        
    - 作用域
        
    - 是否生成符号
        
    - 是否放入 `.data` / `.bss` / `.rodata`
        

---

### 2️⃣ 链接阶段

- 只关心 **有外部链接的符号**
    
- `static`、`const`（默认）不会暴露符号
    

```text
.data     → 可写的全局/静态变量
.bss      → 未初始化的全局/静态变量
.rodata   → const / constexpr
```

---

## 八、工程实践中的推荐原则

1. **能不用全局变量就不用**
    
2. **全局状态 → `static` 限制在 cpp 内**
    
3. **常量 → 优先 `constexpr`**
    
4. **头文件中避免定义非 `constexpr` 的全局变量**
    
5. **跨文件共享 → 明确使用 `extern`**
    

---

## 九、一句话总结

> **C++ 中的“全局 / 静态 / 常量”并不是一个维度的问题，而是：  
> 存储期 + 作用域 + 链接属性 + 常量语义 的组合结果。**


在类中
- **`const` 成员函数的承诺**是：“我不会改变调用我的那个对象的状态”。
    
- **静态成员的状态**被认为是“类级别的状态”，而不是“对象级别的状态”。
