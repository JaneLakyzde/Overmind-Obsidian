# 物理格式化
出场格式化 + 分区, 一般在出厂或装机前完成

1. **划分磁道和扇区**  
    在每个盘面上划分同心圆磁道，再把磁道切成若干扇区。
    
2. **写入扇区结构信息**
    每个扇区通常包括：
    - 扇区头：柱面号、磁头号、扇区号、CRC 等 
    - 数据区
    - 扇区尾：ECC 纠错码等
	建立主引导记录与分区表
    
3. **设置扇区间隙**  
    扇区之间、磁道之间留间隙，避免磁头读写时互相干扰。
    
4. **标记坏道**  
    发现缺陷扇区就标记，避免以后使用。
    
5. **写入伺服信息**  
    很多硬盘在更早的工厂阶段写入伺服图案，用于磁头精确定位。
	

# 逻辑格式化
分区之后, 装系统之前, 核心任务是在分区上建立文件系统结构: 写超级块, 建inode表/文件分配表、初始化空闲空间管理、创建根目录, **将分区收拾成能放文件的样子**

1. **写引导扇区**
    - 分区第一个扇区通常叫 VBR 或 PBR。
    - 里面包含 BPB，即 BIOS Parameter Block，记录扇区大小、簇大小、文件系统类型等。
    - 传统 BIOS 启动时，MBR 引导代码会跳到活动分区的 VBR。
        
2. **建立文件系统元数据**  
    不同文件系统不一样：
    
    - FAT：FAT 表、根目录、数据区
    - NTFS：MFT、MFT 镜像、日志、位图等
    - ext4：超级块、inode、块位图、inode 位图、日志等
        
3. **建立根目录**  
    创建 `\` 或 `/` 根目录，让文件系统有起点。
    
4. **建立空闲空间管理**  
    记录哪些簇/块空闲，哪些已占用。
    
5. **设置卷标、序列号、簇大小等**  
    例如 NTFS 的簇大小、卷标、文件系统版本。
    
6. **可选：扫描坏扇区**
    - 快速格式化：只重建文件系统元数据，不扫描坏道。
    - 完全格式化：可能扫描表面、写零、标记坏簇。
高级格式化只影响该分区，一般不影响其他分区。

# 引导块
- 在 ROM 中保留很小的[[BIOS]]基本输入输出系统, 引导到磁盘引导块中的自举程序 
# 坏块
- 逻辑初始化时会检查坏块, 并在 [[文件结构|FAT]] 上表明不会使用
- 对于复杂的磁盘, 控制器会维护磁盘内的坏块列表, 坏块对上层操作系统透明
	物理格式化时会保留一些备用块, 作为扇区备用


磁盘用时计算:

寻道时间 + 旋转延迟(平均) + 扇区传输时间

# 磁盘高速缓存
| 对比项    | 磁盘高速缓存                                 | 磁盘缓冲存储器                             |
| ------ | -------------------------------------- | ----------------------------------- |
| 英文     | disk cache                             | disk buffer / drive buffer          |
| 核心目的   | 保存磁盘数据副本，利用局部性，<br>减少慢速磁盘访问            | 临时存放传输中的数据，<br>匹配主机与磁盘介质速度，平滑突发 I/O |
| 位置     | 可在 OS 主存、存储控制器、<br>磁盘驱动器内              | 多在磁盘驱动器或 RAID 控制器内                  |
| 管理方    | OS 内核或固件，常用 LRU、ARC、<br>预读、写回等         | 磁盘/控制器固件，常用队列、写合并、<br>重排序、预取        |
| 数据性质   | 磁盘内容的副本，可被多次重用                         | 在途数据，通常写出后释放；<br>读预取部分可重用           |
| 关键指标   | 命中率、减少 I/O 次数                          | 吞吐量、延迟平滑、写合并效率                      |
| 容量     | OS 的 page cache 可达 GB 级；<br>控制器/盘内也可较大 | 硬盘通常几 MB 到几百 MB，<br>企业级/RAID 可更大    |
| 掉电影响   | 若为写回缓存，未刷盘数据会丢                         | 若写缓存未落盘，也会丢；<br>需 FLUSH/FUA/电池保护    |
| 对上层可见性 | OS 可见、可调；对应用通常透明                       | 对 OS 也常透明，表现为设备内部行为                 |
| 典型例子   | Linux page cache、Windows 系统缓存          | HDD/SSD 内置 DRAM 缓存、<br>RAID 卡写缓存    |
