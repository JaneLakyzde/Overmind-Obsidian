# 1. 设备分配时应考虑的因素
1.1 设备的固有属性
	独占设备
	共享设备
	虚拟设备: 独占设备被虚拟技术改造为共享的设备
1.2 设备分配算法
	先来先服务算法 FCFS
	最高优先级优先算法
	
1.3 设备分配中的安全性
- 安全分配方式: 为进程分配一个进程以后将其阻塞
		破坏了请求保持条件, 不会[[死锁]]
		只能串行工作
		
- 不安全分配方式: 进程可以继续执行并申请IO
		可以并行处理, 速度快
		可能发生死锁

# 2. 静态分配与动态分配
- 静态分配: 运行前为其分配全部资源, 结束后归还资源
	破坏了请求保持条件, 不会发生[[死锁]]
-  进程运行过程中动态申请设备资源

# 3. 设备分配管理中的数据结构
- 一个通道控制多个控制器
- 一个控制器控制多个设备
- 是一个[[05_树]]的结构

- 设备控制表 `DCT`: 系统为每个设备配置一张, 用于记录设备情况
	设备类型:
	设备表示符: 物理设备名, 唯一标识
	设备状态:
	指向控制器表的指针: 找到相应控制器的信息
	重复执行次数和时间: 重复执行多次不成功认定为失败
		设备队列的队首指针: 指向正在等待该设备的进程`PCB`队列

- 控制器控制表 `COCT`: 每个设备控制器一张
	设备控制器标识符
	控制器状态
	指向通道的指针
	控制器队列的队首指针
	控制器队列的队尾指针

- 通道控制表 `CHCT`: 每个通道一张
	通道标识符
	通道状态
	通道控制的所有控制器相关信息(控制器表首地址)
	通道队列的队首指针
	通道队列的队尾指针

- 系统设备表 `SDT`: 记录了全部设备的情况
	- 设备表目 * n
		设别类型
		设备标识符
		设备控制表 `SDT` 
		驱动程序入口

# 4. 设备分配的步骤
1. 根据进程请求的[物理设备名]查找 `SDT` , 找到 `DCT`
2. 判断是否空闲, 将进程 `PCB` 挂到设备等待队列中
3. 根据 `DCT` 找到 `COCT` , 将进程挂到控制器等待队列
4. 根据 `COCT` 找到 `CHCT` , 将进程挂通道等待队列
	以上全部分配成功, 即开始工作
- 缺点
	1. 底层细节不透明, 依赖物理设备名, 不方便编程
	2. 同类型设备空闲, 无法灵活调度
- 改进: 实现逻辑设备名(设备类型) 和物理设备名的转换映射

		设置逻辑设备表 `LUT`
