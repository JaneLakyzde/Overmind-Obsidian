在操作系统中，进程调度（又称低级调度）是指按照某种方法和策略，
从就绪队列中选取一个进程，
并将处理机（CPU）分配给它运行。
其目的是实现进程的并发执行。

在考研408的语境中，进程调度有狭义和广义之分：

- **狭义**：仅指“从就绪队列中选中一个要运行的进程”这一决策过程
- **广义**：除了“选择”之外，还包括进程切换
	即让选中的进程投入运行，并将CPU控制权从旧进程转移到新进程的完整过程

- 进程调度是CPU在内核态下完成的
- 进程调度基于[[中断的分类|中断]]机制
- 调度器 = 调度程序

## 调度时机
- 主动放弃
	运行完毕, 正常终止
	运行过程中发生异常
	发生事件, 请求阻塞
- 被动放弃
	进程时间片用完
	有更高优先级进程进入就绪序列
	有更紧急的事件需要处理
- 不可切换
	处理中断时, 不能切换到另一个正常进程/线程
	进程处于内核临界区时(内核态不能被切换到用户态)
	执行原子操作时

- 默认非抢占式, 如果是抢占式, 剩余时间为衡量标准
	作业越短, 优先级越高, 越先被调度

	短作业有利, 长作业不利甚至[饥饿]

# 多处理机调度

## 原则
- 亲和性: 尽量保证同一进程在同一个处理机上持续运行, 减少上下文迁移开销
- 负载均衡: 尽量保证所有 CPU 的负载平衡, 以发挥多处理机的优势

## 公共就绪队列
- 所有 CPU 共享一个公共队列, 天然实现负载均衡
	每个 CPU 访问公共就绪队列时需要上锁
- 软亲和: 调度程序尽量保证一个进程在一个 CPU 上运行, 必要时可以迁移
- 硬亲和: 用户通过系统调用绑定进程到一个固定的 CPU 上
	Linux 两个机制都实现了

## 私有就绪队列
- 为每个 CPU 设置一个私有就绪队列, 很好的保证了亲和性, 但是需要处理负载均衡
- 推迁移: 系统程序周期性检查每个 CPU 的负载, 并将高负载队列中的进程推向低负载
- 拉迁移: 低负载 CPU 会检查并拉取高负载队列中的进程

# 线程切换与上下文更新

## [[PCB|进程]]切换需要改变

1. **程序计数器 PC**  
   保存旧进程执行位置，恢复新进程上次被中断的位置。

2. **通用寄存器**  
   如 AX、BX、CX、DX 等，需要整体保存和恢复。

3. **栈相关寄存器**  
   如栈指针 SP、栈基址指针 BP。  
   不同进程有不同的用户栈，内核栈通常也不同。

4. **程序状态字 PSW/标志寄存器**  
   保存和恢复条件码、中断屏蔽状态等。

5. **页表基址寄存器**  
   如 x86 中的 CR3、PTBR。  
   因为不同进程地址空间不同，页表不同，所以必须切换。

6. **进程资源相关指针**  
   如文件描述符表指针、内存管理信息、信号处理信息等，属于 PCB 中的资源管理信息。

7. **可能的 TLB 刷新**  
   由于地址空间改变，部分 TLB 项可能失效，现代 CPU 也可能用 ASID 减少刷新。

---

## 进程切换不需改变

虽然进程切换涉及大量寄存器更新，但仍有一些内容是**全局共享、不需要随进程切换而改变**的，例如：

1. **全局描述符表寄存器 GDTR**  
   指向内核全局描述符表，所有进程共享，不需要改变。

2. **中断描述符表寄存器 IDTR**  
   指向内核中断描述符表，所有进程共享，不需要改变。

3. **内核代码段、内核数据段选择子**  
   如内核态下的 CS、DS、SS 等段选择子，通常由操作系统全局设置，所有进程进入内核态后使用同一套。

4. **处理机工作模式**  
   进程切换本身发生在内核态，切换前后 CPU 仍然处于内核态，处理机模式不变。

5. **内核全局数据结构**  
   如全局打开文件表、缓冲区缓存、内核页表的高半部分映射等，这些属于系统全局资源，不随进程切换而改变。

6. **Cache 内容**  
   一般不会因为进程切换而强制清空 Cache，除非有特殊的缓存一致性要求。


> **进程切换改变的是“进程私有”的上下文和资源；不改变的是“内核全局”的寄存器、表和数据结构。**

## 线程调度与切换

同一进程内的多个线程共享进程的地址空间和大部分资源，因此线程切换比进程切换轻量。

**线程切换需要改变：**

- 程序计数器 PC
- 通用寄存器
- 栈指针/栈基址寄存器  
  每个线程有自己的用户栈，内核级线程通常也有自己的内核栈。
- 线程状态、优先级等 TCB 信息
- 线程局部存储 TLS 相关寄存器，如 x86 中的 FS/GS

**线程切换不需要改变：**

- 页表基址寄存器  
  因为同一进程内的线程共享地址空间，页表不变。
- 文件描述符表、信号处理信息、内存管理信息  
  这些属于进程级资源，线程共享。
- TLB 中与地址空间相关的部分  
  因为地址空间没变，TLB 不需要因地址空间切换而失效。

所以：

> **线程切换主要切换的是线程私有的运行现场，不切换进程资源。**


| 比较项 | 进程切换 | 同一进程内线程切换 |
|--------|----------|------------------|
| PC、通用寄存器、SP/BP | 需要切换 | 需要切换 |
| 页表基址寄存器 | 需要切换 | 不需要切换 |
| 内核栈 | 通常切换 | 通常切换 |
| 文件描述符表等资源 | 需要切换 | 不需要切换 |
| TLB 地址空间相关项 | 可能失效 | 一般不失效 |
| 切换开销 | 大 | 小 |


如果是**不同进程的线程切换**，本质上相当于进程切换，因为地址空间不同，页表基址寄存器仍然需要切换，开销不会减少。

另外，如果考查**用户级线程**，其切换由用户态线程库完成，操作系统不感知，因此不涉及内核上下文切换，开销更小；但内核级线程切换由操作系统完成，不过同一进程内的内核级线程切换仍然比进程切换轻量。
