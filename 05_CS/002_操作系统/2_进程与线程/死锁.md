## 死锁的概念与原因

- **死锁**: 多个进程因竞争资源而造成的一种僵局, 各个进程都被阻塞
	死锁一定要有两个或两个以上的进程才会导致
	每个进程只能同时申请/拥有一个资源, 不会发生死锁
	区分: [饥饿], 死循环
	
- 发生死锁的原因:
	1. 系统资源的竞争
	2. 进程推进顺序非法
	
- 发生死锁的*必要条件*:
	1. 互斥访问
	2. 不可剥夺
	3. 请求并保持
	4. 循环等待

## 死锁的处理策略

### 死锁预防
1. 破坏互斥条件(例: SPOOLing技术, 加一层抽象层将互斥改造为共享)
		有些资源无法改造, 具有局限性

2. 破坏不可剥夺条件(资源请求无法满足时, 必须释放已占有的资源)
	[饥饿]/反复申请增加系统开销
	
3. 破坏请求并保持条件
	- [[设备的分配与回收|静态分配]]法(系统资源被严重浪费/[饥饿])
	- 逐步释放已使用完成的资源
	
4. 破坏循环等待条件(顺序资源分配法)
	新设备增加麻烦/变成复杂/资源编号与使用顺序不一致造成浪费
	
### 避免死锁
- 安全状态: 系统能按照某种进程推进顺序分配资源, 直至满足每个进程对资源的最大需求
	使每个进程都可以顺利完成, 此时称该序列为安全序列
	若找不到一个安全序列, 则系统处于不安全状态

### 死锁检测和解除

1. **死锁检测**: 构建一个有向图数据结构
	两种节点: 用圆圈表示一个进程, 用方框表示一类资源
	两种有向边: 请求边从进程指向资源; 分配边从资源指向进程
	1. 依次消除不阻塞进程相连的边, 直到无边可消
	2. 死锁定理: 当资源分配图不可完全简化时, 发生了死锁
	- 无环路时, 违反了循环等待条件, 一定不会死锁
	- 
	
2. **死锁解除**: 
	1. 资源剥夺法
	2. 撤销进程法
	3. 进程回退法

## 银行家算法步骤

- 假设本次申请被批准后，系统是否仍然存在一个安全序列，使所有进程最终都能完成
	
1. 检查此次申请是否超过了之前声明的最大需求数
2. 检查此时系统剩余的可用资源是否还能满足这次请求
3. 试探着分配, 更改各数据结构
4. 用安全性算法检查此次分配是否会导致系统进入不安全状态

## 安全性算法步骤
- 安全序列:
	从当前剩余资源出发，寻找一个当前剩余资源能够满足其全部剩余需求的进程；
	假设该进程执行完成后，完成后释放它原来占有的全部资源，使可用资源增加；
	然后继续寻找下一个能够被满足的进程，重复这个过程，直到所有进程都能完成
	
```
1. Work = Available；Finish = false (全部进程)
2. 寻找一个未完成且 Need[i] ≤ Work 的进程：
   若找到，则执行：
       Work = Work + Allocation[i]；
       Finish[i] = true；
       重复步骤2；
   若找不到，则转步骤3。
3. 若所有 Finish 均为 true，则系统安全；
   否则系统不安全。
```
