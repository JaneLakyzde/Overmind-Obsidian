# 1. 基本概念

操作系统（Operating System, OS） 是指控制和管理整个计算机系统的硬件与软件资源，并合理地组织调度计算机的工作和资源的分配，以提供给用户和其他软件方便的接口和环境的程序集合。

* 对下 (Manager)： 作为[[资源管理器]]，它是“大管家”。
    * 管理：处理器（CPU）、内存、I/O 设备、文件（数据）。
    * 目标：安全、高效（提高利用率和吞tǔ量）。
* 对上 (Interface)： 作为用户与计算机硬件之间的接口，提供服务。
    * 用户接口： 允许用户操作计算机。
        * 命令行接口 (CLI)： 如 `bash`, `powershell`。`shell`（命令解释器）本身是一个应用程序，它负责解析用户命令，然后通过[[系统调用]]来执行。
        * 图形用户界面 (GUI)： 如 Windows 桌面、GNOME。GUI 也是一个应用程序，它调用底层的系统调用来响应用户的点击、拖拽等操作。
    * 程序接口（API）： 允许应用程序请求 OS 服务。
        * 最核心的就是 [[系统调用]] 。这是 OS 提供给应用程序的“服务菜单”。
---
## 批处理系统
1. 单道批处理:
	- 内存中只有一道程序
	- 监督程序解决人工与机器速度之间的矛盾, 一批程序自动运行, 无需人工干预
	- 程序之间串行执行
	
2. 多道批处理
	- 多道程序设计与中断机制提高 CPU 利用率
	- 轮流占用 CPU, 首次提出[[2_进程与线程|进程管理]]、[[3_内存管理|内存管理]] 
	- 无法人机交互

## 分时操作系统
1. 将 CPU 时间划分为时间片分配给不同程序
2. 实现了**人机交互**, 用户可以在很短时间内获得相应, 交互性与及时性

## 实时操作系统
- 处理具有精确时间约束的任务
- 可抢占式进程调度 + 中断嵌套 = 保证高优先级任务
1. 硬实时系统: 导弹制导
2. 软实时系统: 飞机订票

# 2. 操作系统的功能

- [[2_进程与线程]]
    * **类比：** 总经理如何调度手下所有的厨师（进程）和服务员（线程）。
    * **做什么：** 决定哪个程序（进程）现在可以使用 CPU。是让 Word 先算一下，还是让音乐播放器先解码？这就是**进程调度**。还包括进程的创建、撤销、同步和通信。

- [[3_内存管理]]
    * **类比：** 管理厨房里有限的“配菜台”（内存/RAM）。
    * **做什么：** 决定给 Word 分配多大台面，给 Chrome 分配多大台面（**内存分配**）。程序关闭时，还要**回收**（Free）台面（**内存回收**）。更高级的还包括地址映射。

-  [[4_文件管理]]
    * **类比：** 管理餐厅的巨大“储藏室”（硬盘/SSD）。
    * **做什么：** 负责食材（数据）的摆放（**存储**）、命名（**文件名**）、取用（**读/写**）、以及安全（**权限**）。它让你能通过 `C:\Users\MyDoc.txt` 这样的路径找到东西，而不是记住“在硬盘第 5 磁道第 3 扇区”。

-   [[5_IO管理]]
    * **类比：** 管理餐厅的所有工具（打印机、烤箱、POS 机、鼠标）。
    * **做什么：** 负责分配和控制所有**输入/输出设备**。当 Word 需要打印时，它向 OS 提出请求（通过系统调用），OS 会协调打印机（设备）来完成工作，并管理等待打印的队列。

 ## [[中断的分类|中断]]的分类

| 类型            | 子类          | 触发原因         | 与当前指令 | 能否返回      | 典型例子           |
| ------------- | ----------- | ------------ | ----- | --------- | -------------- |
| **外中断**       | 可屏蔽中断       | I/O 设备完成     | ❌ 无关  | ✅         | 键盘输入<br>磁盘 I/O |
|               | 不可屏蔽中断NMI   | 严重硬件故障       | ❌ 无关  | ✅<br>可能关机 | 电源故障<br>内存错误   |
| **内中断<br>异常** | **Trap陷阱**  | 程序主动请求       | ✅ 相关  | ✅<br>下一条  | [[系统调用]]<br>断点 |
|               | **Fault故障** | 可恢复错误        | ✅ 相关  | ✅<br>当前指令 | **缺页中断**<br>除零 |
|               | **Abort终止** | 严重<br>不可恢复错误 | ✅ 相关  | ❌         | 非法指令<br>硬件故障   |
- 外中断不回立即进入内核态, 会先进入中断请求线上, [[中断的处理#3. CPU响应中断的条件|满足以下条件时进入中断]]
	1. 当前指令执行完
	2. 中断此时没屏蔽
	3. 没有更高优先级中断
- 调试器就是通过主动插入陷阱指令使程序暂停在对应位置上。

易错点：

| 误区          | 正确理解                                             |
| ----------- | ------------------------------------------------ |
| “系统调用是外中断”  | ❌ 系统调用是 **trap（内中断）**，由 `int` 或 `syscall` 指令主动触发 |
| “缺页中断是外中断”  | ❌ 缺页是 **fault（内中断）**，由 MMU 检测到页表项无效引发            |
| “时钟中断是内中断”  | ❌ 时钟中断是 **外中断**（由硬件时钟芯片发出）                       |
| “所有中断都来自外部” | ❌ 内中断（异常）来自 CPU 内部执行过程                           |

# 3 操作系统的特征


1.  **并发 (Concurrency)**
    * **核心概念：** 宏观上同时发生，微观上交替执行。
    * **辨析：并发 vs. 并行 (Parallelism)**
        * **并行 (Parallelism)：** **同一时刻**，两个任务**同时**在运行。
        
    * **结论：** 单核 CPU 只能并发，不能并行。多核 CPU 可以并发，也可以并行。

2.  **共享 (Sharing)**
    * **核心概念：** 系统中的资源（硬件、软件）可以被多个并发执行的进程共同使用。
    * **共享的两种方式：**
        * **互斥共享 (Mutual Exclusion)：** 某个资源在同一时刻只允许一个进程访问。
            
        * **同时访问 (Simultaneous Access)：** 某个资源在同一时刻允许多个进程访问。
            
    * **关系：** 并发和共享互为前提。没有并发，就不需要共享（一个一个来）；没有共享（比如 CPU 不共享），并发也无从谈起。

3.  **虚拟 (Virtualization)**
    * **核心概念：** OS 把一个物理实体转变为多个逻辑对应物的技术。**“一变多”**。
    * **实现方式：**
        * 时分复用 (Time-sharing) → 虚拟处理器：
            * 通过时分复用技术，将一个物理 CPU 虚拟为多个逻辑 CPU（虚拟处理器），供多个进程轮流使用，让每个进程“感觉”自己独占了 CPU。
        * 空分复用 (Space-sharing) → 虚拟内存：
            * 通过虚拟内存技术，将一个物理内存（如 8GB）虚拟为多个、更大的逻辑地址空间（如每个进程都有 4GB 的地址空间），让每个进程“感觉”自己拥有了连续且巨大的内存空间。

4.  **异步 (Asynchrony)**
    * **核心概念：** 进程的执行不是一贯到底的，而是“走走停停”，因为它们可能需要等待某个事件（如 I/O 操作完成或等待 CPU 资源）。
    * **结果：** 进程的推进速度变得不可预知，但系统**整体效率大大提高**。

# 4 操作系统结构


1.  **分层 vs 模块化: 主要解决代码怎么组织的问题(软件工程维度)**
	- 分层的特点
		1. 易保证系统的正确性
		2. 易扩充和维护
		3. 系统效率低
		4. 层次难以合理定义
	- 网路体系结构也以分层为主, 因为要解决异构互联和标准化
	- 操作系统大多选择模块化, 为了工程实现和性能
	
2. **宏内核 vs 微内核: 哪些功能留在内核态(特权维度)**
	- 宏内核
		性能高: 模块间直接函数调用
		各个模块共享内核数据结构, 配合方便
		内核庞大难以维护
		一个模块崩溃导致整个内核崩溃
		引入可装载内核模块 LKM 实现可扩充性, 但是没有隔离
	- 微内核
		内核实现进程管理、低级存储器管理、中断和陷入处理
		模块间使用消息传递, 需要多次上下文切换, 性能低
		
3. **外核: 内核不做抽象, 只做资源的分配与保护**
	内核给机制和保护，LibOS 给策略和抽象。
	传统系统调用大多变成 LibOS 里的用户态库函数调用
	1. 代价是应用/LibOS 复杂、抽象碎片化、全局协调弱
	2. 收益是灵活、可专用优化、减少通用抽象开销

# 5 [[OS引导]]

从按下电源键到看到桌面，OS 是如何启动的？

1.  **通电 & BIOS/UEFI 启动：**
    * CPU 通电，开始执行主板 ROM（只读存储器）上的**BIOS** (基本输入输出系统) 或 **UEFI** (更现代的接口)。
    
2.  **加电自检 (POST)：**
    * BIOS/UEFI 对硬件（CPU, 内存, 显卡）进行基本检查。
    
3.  **查找引导设备：**
    * BIOS/UEFI 按照设定的顺序（如 硬盘 > U盘 > 网络）查找引导设备。
    
4.  **加载引导加载程序 (Bootloader)：**
    * **传统 BIOS (MBR 方案):** 读取硬盘的**第一个扇区**（称为**MBR**，主引导记录）。MBR 很小，它包含一小段代码（Bootloader）和分区表。
    * **现代 UEFI (GPT 方案):** 从一个特殊的 **ESP 分区**中加载 Bootloader 程序（如 GRUB 或 Windows Boot Manager）。
    
5.  **OS 内核加载：**
    * Bootloader (如 GRUB) 的任务是在文件系统中找到完整的操作系统内核文件（如 Linux 的 `vmlinuz`）。
    * Bootloader 将内核文件加载到 RAM（内存）中。
    
6.  **OS 内核启动：**
    * Bootloader 将 CPU 的控制权交给内存中的 OS 内核。
    * OS 内核开始“接管”计算机：初始化各种管理器（进程、内存、设备驱动等），加载系统服务，最终启动用户界面（如登录窗口或桌面）。

# 6 [[虚拟机]]

* **概念：** 虚拟机 (VM) 是一个**应用程序**，它在你的“宿主操作系统”（Host OS，如 Windows 11）上模拟了一整套完整的计算机硬件（虚拟 CPU、虚拟内存、虚拟硬盘）
* **目的：** 你可以在这个“虚拟硬件”上安装一个完全独立的“客户操作系统”（Guest OS，如 Ubuntu Linux）。
* **分类：**
    * **Type-1 (裸金属型)：** Hypervisor（虚拟机管理器）**直接运行在物理硬件上**。OS 都是作为 Guest 运行在它之上。运行在最高优先级上, 可以直接分配未经抽象的物理硬件
        * *例子：* VMware ESXi, Proxmox VE。 (常用于服务器)
    * **Type-2 (托管型)：** Hypervisor 作为**一个应用程序**运行在你的**宿主 OS** 上。
        * *例子：* **VMware Workstation**, **VirtualBox**, Parallels Desktop。 (常用于个人电脑)
