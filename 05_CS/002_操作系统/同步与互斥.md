首先, 并发程序是异步独立进行的, 则表示其会不可预知的向前推进
# 基本概念
- **临界资源**: 一次只能允许一个进程使用的资源叫做临界资源
	**临界区/临界段**: 进程中访问临界资源的那段代码
- **同步**: 直接制约关系
- **互斥**: 间接制约关系
- **同步机制的四个原则**
	1. 空闲让进
	2. 忙则等待
	3. 有限等待
	4. 让权等待

# 软件实现方法

## 单标志法
```
1.
2.
3.
4.
```
- 用一个共享变量 `turn` 表示“轮到谁进入临界区”
	天然保证两个进程不可能同时进入临界区
- 必须严格轮流进入
	p0 进入后让给 p1, 但是 p1 不进入, 将导致 p0 无法再次使用临界资源
- 不满足[空闲让进]
## 双标志先检查
```
1. 检查对方是否上锁, 如果没有, 进入下一步
2. 自己上锁
3. 使用
4. 解锁
```
- 两个进程同时检查对方是否上锁, 随后两人同时上锁同时使用
- 不满足[忙则等待]
## 双标志后检查
```
1. 自己先上锁
2. 检查对方是否上锁, 如果没有, 进入下一步
3. 使用
4. 解锁
```
- 两个进程可以同时申请上锁, 随后检查到对方上锁, 开始互相等待
- 不满足 [空闲让进 有限等待] 导致 [饥饿]
## peterson 算法
```
1. 先表明意愿 自己 flag = true
2. 表达谦让(给对面枪) turn = 对方
3. 检查对方意愿, 对方也有意愿且自己是最后一个表达谦让的时, 等待
	当对方想开且有枪时, 不能进入临界区
4. 使用
5. 撤销意愿
```
- `while`  循环忙等导致其不满足[让权等待]

# 硬件实现方法
## 中断屏蔽方法
- 限制了 CPU 交替执行程序的能力, 系统效率明显降低
- 将关中断权限滥用很危险
- 不适用于多处理机系统
## 硬件指令方法
- `TestAndSet` TS指令属于[[原语]], 可以读出指定表之后将该标志设置为真
	实现简单, 适用于多处理机
	无法进入临界区的进程会占用 CPU 循环执行 TS 指令, 不满足[让权等待]
- `Swap` 指令, 也叫 XCHG指令
	实现简单, 适用于多处理机
	无法进入临界区的进程会占用 CPU 循环执行 TS 指令, 不满足[让权等待]
```
1. 拿取旧牌子
2. 挂上有人使用中
3. 检查换下来的牌子是是否有人
4. 有人持续循环, 无人直接进入 //只有系统一开始的是无人, 所以只有一个人能进
```
- 都类似于[自旋锁]

# 互斥锁
`mutex lock` 使用两个函数来限制进程能否进入临界区执行相关操作
- 忙等待, 需要连续调用 `acquire()` 违反了让权等待问题
- 常用于多处理及系统, 一个核忙等, 其他核照常工作
- 不适用于单处理机系统, 忙等过程中不可能解锁
