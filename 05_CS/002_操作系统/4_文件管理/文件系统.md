## 系统打开文件表: 
- 只有一张, 记录所有打开文件的情况
	访问计数: 可以确认是否有进程正在使用该文件, 拒绝删除
	`inode` 指针 (具体问题具体分析)
- 有些题目中, 会包含文件的所有属性 `inode`
- OS 导论中, 再次打开同样的文件不会额外建立表项

>系统打开文件表里可以有同一文件的多个不同表项，它们都指向同一个 inode。  因为系统打开文件表按“打开实例”建表，inode 按“文件”唯一。独立 `open` 产生多个表项、独立偏移；`dup`/`fork`/传 fd 共享同一个表项、共享偏移。

## 进程打开文件表: 
- 每个进程一张, 存在[[PCB]]中
	文件描述符
	读写指针: 进程对文件的读写操作进行到的位置
	访问权限: `rwx` 
	指针: 指向系统打开文件表表项
	
- 具体过程
```
open("a.txt"):
路径参数解析 
-> 目录项 a.txt 
-> 找到索引结点inode 123   //或者是对应 FCB
-> 建立系统打开文件表项 S
-> 进程 fd 表[3] = &S     //fd 是下标，表项是指针
-> 返回 fd = 3

read(3, buf, n):
-> fd=3 
-> 进程 fd 表[3]          //找到进程打开文件表中的指针
-> S 
-> 内存 inode 123         //索引结点，保存文件元数据、数据块位置等
-> 根据偏移读数据块 
-> 拷贝到用户 buf
```
