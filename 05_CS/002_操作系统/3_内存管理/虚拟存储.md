# 2. 请求分页
## 2.1 基础概念
- 页表机制: 主要关注新增条目
	0. 页号+物理块号
	1. 状态位
	2. 访问字段
	3. 修改位
	4. 外存地址
	
- [[中断的分类|缺页中断]] 
- [[多级存储系统|地址变换]]: 主要关注页不在内存中的流程
	1. 保留现场
	2. 从外存中找到缺页
	3. 如果内存满了
		3.1 选择一页换出
		3.2 如果修改过, 则写回外存
	4. OS 让 CPU 启动 I/O
	5. 将一页从外存换入内存
	6. 修改页表
	
## 2.2 内存分配策略
- 固定分配局部置换:
	[驻留集]大小不变, 只能置换自己的物理块
- 可变分配全局置换: 
	[驻留集]大小可变, 可以将别的进程的物理块置换到外存
	只要缺页, 就分配给缺页进程(驻留集增加)
- 可变分配局部置换: 
	[驻留集]大小可变, 只能置换自己的物理块
	根据缺页的频率, 将空闲物理块动态的分配给该进程
## 2.3 调入方式

### 物理块调入
1. 平均分配算法
2. 按比例分配算法
3. 优先权分配算法
### 页面调入
- 时机
	1. 预调页策略(首次调入)
	2. 请求调页策略
- 位置
	对换区
	- 对换区常用==连续分配方式==组织磁盘块(扇区), 因此读写速度**更快**
	- 若对换区空间足够, 所需页面将从对换区掉入, 
	在进程运行前需将与进程有关的文件从文件区拷贝到对换区
- 文件区
	- 文件区常用==离散分配方式==组织磁盘块, 因此读写速度**更慢**
	- 如果没有足够的对换区空间, 凡是不会被修改的文件都从文件区调入, 这样换出的时候不用写回磁盘, 对于可能修改的部分调到对换区
- UNIX 方式
	- 凡是未运行过的页面都从文件区调入
	- 运行过被换出的页面放在对换区, 下次从对换区调入
	- 允许页面共享, 此时无需从对换区调入

# 3. [[页面置换算法]]
1. 最佳OPT置换算法: 最佳
2. 先进先出FIFO置换算法: [[Belady 异常]]
3. 最久未使用LAU置换算法: [[Cache]]中也有使用, 性能好, 开销大
4. 时钟CLOCK置换算法:
	又称为最近未使用算法NRU
	最多需要两轮扫描(N+1), 扫描过的访问位置为 0
5. 改进型CLOCK置换算法:
	四轮

# 4. 抖动和工作集
- 抖动:
	由于分配给每个进程的物理块太少, 运行时频繁地缺页
	导致进程的大部分时间都用于页面换入/换出
	
- 驻留集:
	请求分页管理中, 给进程分配的物理块/页框的集合
	太大浪费, 太小抖动频繁
	
 - 工作集:
	 进程实际上在使用的页面的集合
	 驻留集需要大于工作集
