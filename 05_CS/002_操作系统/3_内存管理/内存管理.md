## 离散分配管理

### 基本分页
- 将主存/进程划分为大小相等的页框/页, 将一个进程的所有页离散的调入页框
	页表: 一个进程对应一张页表, 页表起始地址放在[[PCB]]中
	快表: [[多级存储系统|TLB]] 
	地址结构: (页号) + 块号 + 业内偏移量
	
### 基本分段
- 从程序员的角度, 为了方便编程, 将代码按照逻辑分段, 通常大小不一, 
	**不对主存做任何划分**
	(段号) + [段长] + 段内地址  // 对于长度不一的文件, 也可以采用类似的方案
	段长对应段的起始地址, 段内地址对应地址偏移量
- **共享段表是 OS 用于管理共享段的系统数据结构，不是进程进行普通地址转换时直接查询的表。**
	
	当进程申请共享某个段时，OS 查询共享段表：
	**不存在** → 创建共享段、分配物理内存、建立共享段表项，并映射到进程自己的段表
	**已经存在** → 找到已有共享段，将其映射到当前进程的段表，并增加引用计数
	**计数变为 0** → 说明没有进程继续使用该共享段，OS 回收对应物理内存并删除段表项
- 因此核心关系是：
	共享段表 → OS管理共享段表→ OS管理
	进程段表 → CPU地址转换进程段表→ CPU地址转换
	多个进程的段表 → 同一个物理共享段
### 基本段页
- 先把用户程序分成段, 再把每个段分成页, 并为每个段赋予一个段名
	**主存划分页框**
	段号 + 段内页号 + 业内地址
- 具体过程:
	用段号在段表中找到页号, 
	用页号在页表中找到段内页号, 
	再用业内地址和段内页号拼凑出物理地址
- 易错点总结:
	1. 页与页框: 大小相等
	2. 页与页表项: 页表项中保存的是页号到页框号的映射, 一个进程有多少页,  页表里有多少项
	3. 页表与页表项: 页表由页表项组成
	4. 页表与页框: 页表在主存中, 放在主存内核取区, 可以说页表在页框里
		普通页表可以占多个页框, 多级页表的每个页表最多只能占一个页框

### 多级页表
- 构造: 多为两级, 将页表(二级) 分页, 离散的存放在内存里, 
	再来一张页表(一级/顶级/页目录)记录他们的位置
- 特点: 多级页表的每个页表最多只能占一个页框
