- 形如一组打包好的库函数
	这些函数的功能需要由 OS 内核来实现
	系统调用提供了用户程序和 OS 内核之间的接口
	应用程序通过系统调用来获得 OS 内核的服务

# 例: READ() 系统调用
- `read()`  只是一个库函数, 并非真正的系统调用
	系统调用不会显式的出现在用户代码中

```assembly
read:
    mov    $0, %rax      ; 系统调用号 (0) -> %rax
    mov    %rdi, %rbx    ; 参数1: fd -> %rdi
    mov    %rsi, %rcx    ; 参数2: buf -> %rsi
    mov    %rdx, %rdx    ; 参数3: count -> %rdx
    syscall              ; 使用 'syscall' 指令进入内核
    cmp    $-4095, %rax  ; 检查返回值是否错误 (Linux约定)
    jae    .Lerror       ; 若出错则跳转
    ret
```

- 注意: 先传递系统调用参数, 再执行陷入指令

- `syscall`会由硬件发起一次[[中断的分类|自陷中断]], 从而允许用户去执行操作系统的内核态操作
	软中断: 软件模拟中断

- 库函数 `read()` 偷偷执行了一个软中断来发起真正的系统调用, 内核执行完服务程序后, 操作系统通过 `sysret` 指令调用硬件修改 CPU 中的[[CPU 的工作模式|模式位]], 使其回到用户态
