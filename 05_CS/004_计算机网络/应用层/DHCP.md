客户段使用 UDP 端口号 68 , 服务器 UDP 端口号为 67

用不了[[ARP]]协议, 只能发送广播帧(网络层), 在链路层实际上是单播的

# DORA 四大报文

| 报文类型                  | 发送方向             | **源IP地址** (Src IP)       | **目的IP地址** (Dst IP)               | **源MAC地址** (Src MAC) | **目的MAC地址** (Dst MAC)          |
| :-------------------- | :--------------- | :----------------------- | :-------------------------------- | :------------------- | :----------------------------- |
| **Discover** <br>(发现) | 客户端<br>→ <br>服务器 | `0.0.0.0` <br>(客户端无IP)   | `255.255.255.255` <br>(本地广播)      | 客户端MAC               | `FF-FF-FF-FF-FF-FF` <br>(二层广播) |
| **Offer** <br>(提供)    | 服务器<br>→ <br>客户端 | DHCP**服务器**的IP <br>      | `255.255.255.255` <br>(广播，见下方注释①) | DHCP**服务器**的MAC      | **客户端MAC** <br>(**单播**，见下方注释②) |
| **Request** <br>(请求)  | 客户端<br>→ <br>服务器 | `0.0.0.0` <br>(尚未正式获得确认) | `255.255.255.255` <br>(广播，见下方注释③) | 客户端MAC               | `FF-FF-FF-FF-FF-FF` <br>(二层广播) |
| **Ack** <br>(确认)      | 服务器<br>→ <br>客户端 | DHCP**服务器**的IP           | `255.255.255.255` <br>(广播，见下方注释①) | DHCP**服务器**的MAC      | **客户端MAC** <br>(**单播**)        |
|                       |                  |                          |                                   |                      |                                |
# DHCP 四次握手（DORA）交互流程

> **核心要点**：DHCP 使用 **UDP** 协议，服务器端口 `67`，客户端端口 `68`。在客户端正式获得 IP 地址前，**所有报文均以广播方式发送**（目的 IP 为 `255.255.255.255`），以规避单播在未配置 IP 时的接收难题。

## 一、四报文全广播交互总览

| 阶段  | 报文类型     | 源 IP      | 目的 IP             | 源 MAC  | 目的 MAC              | 传输方式   |
| --- | -------- | --------- | ----------------- | ------ | ------------------- | ------ |
| 1   | DISCOVER | `0.0.0.0` | `255.255.255.255` | 客户端MAC | `FF:FF:FF:FF:FF:FF` | **广播** |
| 2   | OFFER    | 服务器 IP    | `255.255.255.255` | 服务器MAC | 客户端 MAC             | **广播** |
| 3   | REQUEST  | `0.0.0.0` | `255.255.255.255` | 客户端MAC | `FF:FF:FF:FF:FF:FF` | **广播** |
| 4   | ACK      | 服务器 IP    | `255.255.255.255` | 服务器MAC | 客户端 MAC             | **广播** |

> [!note] 考研标准
> 按谢希仁《计算机网络》等主流教材的简化模型，DHCP 交互为 **四次全广播**。即便某些实现中链路层可能使用单播 MAC 地址，但 **IP 层始终使用广播地址**，考试中一律按“都是广播”作答。

## 二、分步详解

### DISCOVER
- **触发时机**：客户端刚接入网络，无任何 IP 配置信息。
- **内容**：客户端会填入自己的 MAC 地址，并请求一个 IP 地址。
- **为何必须广播**：客户端不知道网络中有哪些 DHCP 服务器，更不知道它们的 IP，只能全网广播寻找 UDP 67

### OFFER
- **触发时机**：DHCP 服务器收到 Discover 后，从地址池数据库中选出一个 IP 地址，向客户端 UDP 68 发出 Offer
- **内容**：包含预分配的 IP 地址、子网掩码、租约期限、服务器标识、事务ID
- **为何是广播**：虽然服务器已经知道客户端的 MAC 地址，但在客户端尚未正式“拥有”此 IP 之前，若发送 IP 单播，**客户端网络协议栈会因目的 IP 不属于自己而丢弃**。因此 IP 层必须填 `255.255.255.255`，让客户端能无条件接收。

### REQUEST
- **触发时机**：客户端可能会收到多个服务器的 Offer，它选择一个，然后发送 Request。
- **为何必须广播**：
  1. **通知落选的服务器**：广播能让其他发出 Offer 的服务器知晓自己未被选中，及时回收预分配的 IP。
  2. **客户端仍未正式获得 IP**：此时客户端 IP 还是 `0.0.0.0`，同样无法使用单播，所以必须继续广播。
- **特殊情况**：续租或重启确认旧 IP 时，可单播给特定服务器，但 DORA 初始流程中按广播记忆。

### ACK
- **触发时机**：服务器收到 Request 后，确认将此 IP 正式租给客户端。
- **内容**：包含最终确认的 IP、网关、DNS 服务器、租约时间等全参数。
- **为何是广播**：与 Offer 同理，虽然此时客户端已具备使用该 IP 的条件，但为**保证客户端可靠接收**，IP 层仍发送广播，全网都可收到，客户端再根据 MAC 或事务 ID 取出属于自己的报文。**考研中严格按广播记忆。**
- 主机还会选择使用 [[ARP]] 进行 IP 检测对应 IP 是否已经被使用

# 租用期
- 0.5 倍租用期时,会再次发送 `DHCP REQUEST` 单播, 收到 `ACK`则更新租用期, 收到 `NACK` 则立即停止使用 IP 并发送 `DHCP DISCOVER` 报文
- 0.875 倍租用期时, 若没有收到 DHCP 服务器的请求, 则再次发送 `DHCP REQUEST` 广播报文请求, 后续流程一致
- 租用期到期时, 立即停止使用当前IP地址并重新发送 `DHCP DISCOVER`报文
- 主机可以随时主动断开/释放链接
