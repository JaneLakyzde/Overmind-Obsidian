### IPv6 地址
- 压缩记法
	每16位段内的前导零可以省略
	可以用双冒号来替代连续出现的多个零, 只能使用一次双冒号
- 地址结构
	n 位前缀 + 128-n 位接口标识符
- 分类
	1. 未指明地址、环回地址
	2. 多播地址
	3. 本地链路单播地址
	4. 全球单播地址
- 三类IPv6目的地址
	单播
	多播
	任播
- 资源分配
	CIDR
	即插即用
	DHCP
	可以在源主机分片, 不能在中间路由器分片
	

### IPv6 首部

```
+---------------------------------------------------------------+
|Version| Traffic Class |           Flow Label                  |
+---------------------------------------------------------------+
|         Payload Length        |  Next Header  |   Hop Limit   |
+---------------------------------------------------------------+
|                                                               |
+                                                               +
|                     Source Address (128 bit)                  |
+                                                               +
|                                                               |
+---------------------------------------------------------------+
|                                                               |
+                                                               +
|                  Destination Address (128 bit)                |
+                                                               +
|                                                               |
+---------------------------------------------------------------+
|                 Extension Headers (if any)                    |
+---------------------------------------------------------------+
```

### Version
- **长度**：4 bit
- **含义**：IP 协议版本
- **IPv6 取值**：`0110`，即 `Version = 6`
- **作用**：告诉设备这是 IPv6 数据报，而非 IPv4

### Traffic Class
- **长度**：8 bit
- **作用**：标识数据重要性，用于 QoS 和拥塞控制
- **类似 IPv4**：DSCP / TOS

| 数据类型 | 优先级 |
| ---- | --- |
| 视频会议 | 高   |
| 在线游戏 | 高   |
| 普通网页 | 中   |
| 下载   | 低   |

> 路由器可据此进行优先转发、QoS 标记和拥塞控制。

### Flow Label
- **长度**：20 bit
- **性质**：IPv6 新增字段
- **作用**：标识哪些包属于同一条数据流（Flow）

**示例：一场视频会议**
```
你
↓
视频包1 (Flow Label = X)
视频包2 (Flow Label = X)
视频包3 (Flow Label = X)
视频包4 (Flow Label = X)
```

> 路由器无需逐包分析，可直接根据流标签识别同一连接，提高 QoS、实时通信效率与转发速度。

**考试常考**：IPv6 新增 Flow Label。

### Payload Length
- **长度**：16 bit
- **含义**：IPv6 首部**之后**的长度
- **注意**：**不包含** 40 字节固定首部

**示例**：
- IPv6 Header：40 B
- 后面 TCP Header：20 B
- HTTP 数据：1000 B
- **Payload Length** = `20 + 1000 = 1020 Byte`（不是 1060）

### Next Header
- **长度**：8 bit
- **作用**：指明 IPv6 首部后面跟着什么（扩展首部或上层协议）

**常见取值**：

| Next Header 值 | 含义              |
| -------------- | ----------------- |
| 6              | TCP               |
| 17             | UDP               |
| 58             | ICMPv6            |
| 43             | Routing Header    |
| 44             | Fragment Header   |
| 59             | No Next Header    |

> 扩展首部链式结构：每一级都通过 `Next Header` 指示下一层，例如 `IPv6 → Hop-by-Hop → Routing → TCP`。

### Hop Limit
- **长度**：8 bit
- **作用**：防止数据包死循环
- **对应 IPv4**：TTL
- **区别**：IPv4 TTL 最初按时间设计，后改为跳数；IPv6 直接正名为 **Hop Limit**

> 例：初始 64 → 经过一个路由器变为 63 → 减至 0 则丢弃。

### Source Address
- **长度**：128 bit
- **示例**：`2001:db8::1`

### Destination Address
- **长度**：128 bit
- **示例**：`2408:8000::100`

## IPv6 去掉了哪些 IPv4 字段？

| IPv4 字段          | IPv6 是否保留 | 原因                           |
| ------------------ | ------------- | ------------------------------ |
| IHL（首部长度）    | ❌             | 首部固定 40B，无需此字段       |
| Header Checksum    | ❌             | 由链路层和传输层负责校验，减少路由器计算开销 |
| Identification     | ❌（移至扩展首部）| 仅分片时需要                   |
| Flags              | ❌（移至扩展首部）| 同上                         |
| Fragment Offset    | ❌（移至扩展首部）| 同上                         |
| Options            | ❌（改为扩展首部）| 保持基本首部固定长度           |

---

## 四、IPv6 新增了哪些字段？

| 新字段         | 作用                             |
| -------------- | -------------------------------- |
| Traffic Class  | QoS、优先级                      |
| Flow Label     | 标识同一数据流，提高实时业务处理效率 |
| Next Header    | 指示后续扩展首部或上层协议       |

## IPv4 与 IPv6 首部对比

| 项目           | IPv4          | IPv6             |
| -------------- | ------------- | ---------------- |
| 地址长度       | 32 bit        | 128 bit          |
| 首部长度       | 20～60 B      | 固定 40 B        |
| 校验和         | 有            | 无               |
| TTL / 跳数限制 | TTL           | Hop Limit        |
| 服务类型       | TOS           | Traffic Class    |
| 流标签         | 无            | 有               |
| 分片字段       | 基本首部中    | 扩展首部中       |
| 可选字段       | Options       | Extension Header |
| 首部是否固定   | 否            | 是               |

## 必背考点

- IPv6 基本首部固定 **40 字节**
- 地址长度为 **128 bit**
- **没有首部校验和**（Header Checksum）
- TTL 改名为 **Hop Limit**
- 新增 **Flow Label**（流标签），用于标识同一数据流
- Options 不再放入基本首部，改为 **扩展首部**
- 分片相关字段（Identification、Flags、Fragment Offset）移至**分片扩展首部**，仅在需要分片时出现
- 基本首部通过 **Next Header** 字段指示后续扩展首部或上层协议（TCP、UDP、ICMPv6 等）
