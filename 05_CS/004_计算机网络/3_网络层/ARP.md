# 一、ARP 基本概念

- **全称**：Address Resolution Protocol（地址解析协议）
- **作用**：**根据 IP 地址获取对应的 MAC 地址**，实现从网络层到数据链路层的映射。
- **网络层次**：属于**网络层**，但其报文封装在数据链路层帧中，服务于链路层寻址。
- **适用范围**：仅在同一个广播域（局域网）内有效，不能跨路由器。

---

# 二、ARP 工作流程

### 1. 同网段主机通信
假设主机 A（IP_A / MAC_A）要发数据给主机 B（IP_B / MAC_B 未知）：

1. **查缓存**：A 先在本地 **ARP 高速缓存** 中查找 IP_B 对应的 MAC。
2. **缓存未命中**：A 发送 **ARP 请求报文**（广播）：
   - 目的 MAC 地址：`FF-FF-FF-FF-FF-FF`
   - 内容：“谁是 IP_B？请告诉 IP_A。”
3. **广播到达 B**：局域网内所有主机收到，只有 IP_B 匹配的主机 B 处理。
4. **B 单播应答**：B 向 A 发送 **ARP 响应报文**（单播）：
   - 目的 MAC 地址：MAC_A
   - 内容：“我是 IP_B，我的 MAC 是 MAC_B。”
   - 同时 B 会将 A 的 IP-MAC 映射**动态存入自己的 ARP 缓存**。
5. **A 收到响应**：将 IP_B ↔ MAC_B 映射写入缓存，之后封装数据帧发送。

### 2. 跨网段通信
若 A 和 B **不在同一网络**（通过路由器 R 连接）：

- A 发现目标 IP 不在本网段 → 将数据包发给**默认网关**。
- A 需要在帧中填入**网关接口的 MAC 地址**，而不是目标主机 B 的 MAC。
- 因此 **A 的 ARP 请求解析的是网关 IP 对应的 MAC**。
- 路由器收到后，拆帧取包，根据路由表转发，到了目标网络再执行该网段的 ARP 解析。

> **结论**：ARP 请求只在本网段广播，跨网段通信时，源主机 ARP 解析的是**下一跳路由器的 MAC**，不是最终目的主机的 MAC。

# 三、ARP 报文格式

ARP 报文直接封装在以太网帧（类型字段 0x0806）中。主要字段：

| 字段      | 长度  | 说明                       |
| ------- | --- | ------------------------ |
| 硬件类型    | 2字节 | 以太网为 `1`                 |
| 协议类型    | 2字节 | IPv4 为 `0x0800`          |
| 硬件地址长度  | 1字节 | MAC 地址长度，值为 `6`          |
| 协议地址长度  | 1字节 | IP 地址长度，值为 `4`           |
| 操作码（OP） | 2字节 | 请求为 `1`，响应为 `2`          |
| 发送端硬件地址 | 6字节 | 源 MAC                    |
| 发送端协议地址 | 4字节 | 源 IP                     |
| 目标硬件地址  | 6字节 | 请求时填 `00-00-00-00-00-00` |
| 目标协议地址  | 4字节 | 欲解析的目标 IP                |

> 注意：ARP 请求/响应不含 IP 首部，直接从数据链路层封装。

# 四、ARP 缓存与超时

- **ARP 高速缓存**：每台主机维护的 IP ↔ MAC 映射表，有老化时间。
- **动态条目**：通过 ARP 自动学习，通常 **生存时间（TTL）为 20~30 分钟**，过期删除。
- **静态条目**：手工配置，永久有效。
- **查看命令**：
  - Windows：`arp -a`
  - Linux：`arp -n`

# 五、两种特殊 ARP

### 1. 免费 ARP（Gratuitous ARP）
- 主机在**开机或 IP 变化**时，主动发送一个 ARP 请求，目标 IP 就是**自己的 IP**。
- 作用：
  1. **检测 IP 地址冲突**：如果收到应答，说明局域网内有其他主机使用了相同 IP。
  2. **更新全网缓存**：其他主机会将自己的 IP-MAC 映射刷新到它们的 ARP 缓存中（常用于集群/主备切换）。

### 2. 代理 ARP（Proxy ARP）
- 路由器**代替不在本网段的目标主机**应答 ARP 请求。
- 场景：源主机认为目标和自己同网段（子网掩码配置过长），实际上目标在另一网络。
- 路由器用自己的 MAC 地址响应，之后代为转发数据包。
- **注意**：代理 ARP 会隐藏物理网络细节，可能带来安全隐患和环路风险，现网较少使用。

# 六、ARP 与相关协议对比

| 协议       | 方向       | 解决问题                     | 报文方式           |
| -------- | -------- | ------------------------ | -------------- |
| **ARP**  | IP → MAC | 已知目标 IP，求对应的 MAC         | 请求广播，应答单播      |
| **RARP** | MAC → IP | 已知自己 MAC，求自己的 IP         | 请求广播，应答单播      |
| **DHCP** | 自动配置 IP  | 终端自动获取 IP、掩码、网关等         | 基于 UDP，初始四次广播  |
| **ICMP** | 差错与诊断    | 检测网络连通性（Ping/Traceroute） | 单播（差错），可广播（询问） |

> **ARP 与 RARP 区别**：本质反向，RARP 已被 [[DHCP]] 淘汰。
