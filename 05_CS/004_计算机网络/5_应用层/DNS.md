DNS = 域名空间 + 分布式数据库 + 域名服务器

域名便于记忆, 输入域名后, 现在高速缓存中查看域名对应IP地址, 如果没有, 去查询 DNS 服务器中的数据库得到目标 IP 地址
- 防止 DNS 服务器压力过大, 使用==层次结构命名树==的分布式域名系统
- 大多数 DNS 都在本地解析
- 一个域名可以对应多个 IP [[CDN]], 一个 IP 也可以对应多个域名 (虚拟主机)
因特网采用层次树状结构的域名结构
$$ .三级域名.二级域名.顶级域名$$
各级域名由其上一级的域名管理机构管理, 顶级域名由 ICANN 管理

# 域名

- 国家顶级域名nTLD: .cn .us .uk
- 通用顶级域名gTLD: .com .net .org .edu
- 反向域arpa: 用于反向域名解析, 即IP地址反向解析为域名
	国家顶级域名下注册的二级域名由国家自行决定
	注意! 二级域名可以和顶级域名相同


# 分布式存储
DNS 使用分布在各地的域名服务器来实现域名到 IP 的转换

1. 根域名服务器 `/`
	==13个不同IP地址==, 会自动转发到最近的服务器
	根域名服务器通常不直接对域名进行解析, 而是返回[顶级域名服务器]的IP地址
	
2. 顶级域名服务器 `.com` **Top-Level Domain** 
	告知“本 TLD 下某域名的权威服务器地址”
	
3. 权威域名服务器 `xyz.com`
	存放并返回某具体域名的最终记录 `A/NS/CNAME/MX`
	
4. 本地域名服务器/默认域名服务器 `abc.xyz.com`
	起代理的作用, 将报文转发到上述域名服务器的等级结构中, 分布广泛
	用户最近的入口; 接收用户的递归请求; 缓存; 代理向上做迭代/递归查询

# 查询过程

- 递归查询: 高级服务器依次替本地服务器查到最终结果
- 迭代查询: 高级服务器只高速你要去查哪个服务器
	用户主机和本地域名服务器之间一般都发送==一条==递归查询, 
	本地域名服务器与服务器之间一般都是==多次==迭代查询
	由本地域名服务器不断发出请求, 缓解其他服务器压力
- 高速缓存
	本地域名服务器和用户主机都有, 缓存命中时不需要再访问服务器
	每项设有计时器, 保证时效性和正确性; 过期后直接丢弃不会重新请求


DNS报文使用 [[UDP]] 协议进行封装, 运输层端口号为53

|类型|含义|
|---|---|
|`A`|把域名解析到 IPv4 地址|
|`NS`|指定该域名的权威名称服务器|
|`CNAME`|别名记录，把域名指向另一个规范域名|
|`MX`|邮件交换记录，指定接收该域邮件的服务器|
