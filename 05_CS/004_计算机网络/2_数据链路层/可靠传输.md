可靠传输是目标, 自动重传请求ARQ是方法
	差错检测 + ACK 确认 + 超时重传 + 序号

# 连接性和可靠性的基本概念

- **连接性**: 通信双方建立某种逻辑关联, 并维护相关状态
	例如 TCP 连接中, 双方需要维护序号、确认号、窗口大小、连接状态等信息

- **不可靠**: 不可靠不是说一定会出错, 而是说协议本身**不负责恢复错误**
	误码、丢失、乱序、重复

PPP: 面向连接不可靠
以太网 802.3: 无连接不可靠
无线局域网 802.11: 无连接可靠
IPv4: 无连接不可靠的数据包服务
UDP: 无连接不可靠
TCP: 面向连接可靠

虚电路是面向连接的, 但是是否可靠取决于具体协议实现

- 连接: 建立类似虚电路的逻辑关联和状态
- 可靠: 正确完整有序的数据传输,
	不可靠会直接丢弃有误码的数据包, 后续什么也不做
	
| 连接性 \ 可靠性 | 可靠          | 不可靠                     |
| :-------: | :---------- | :---------------------- |
| **面向连接**  | TCP<br>     | PPP                     |
|  **无连接**  | 无线局域网802.11 | 以太网802.3<br>IPv4<br>UDP |
- 可靠传输的核心手段:
1. 差错检测
2. 确认机制
3. 超时重传: 超时的时间必须大于 RTT
4. 序号机制
5. 滑动窗口
6. 流量控制: 接收方向发送方反馈信息                                                                                                                                                                                                                

# 停止等待
- 发送方每发送一个数据帧, 就停止发送, 等待接收方的确认 ACK; 收到 ACK 后, 才发送下一个数据帧
- 至少需要 1 bit 序号
- 适合低速短延迟链路, 简单但是信道利用率低
- 利用率: $U = \frac{T_D}{T_D+RTT+T_A}$
# 回退N帧
- 发送方连续发送多个数据帧, 接收方按序接收; 如果中间某一帧出错, 后面的帧全部丢弃, 发送最近一个按序到达的帧的累积确认, 等待发送方超时重传
- 发送窗口 > 1 ; 接收窗口 = 1 ; **累计确认**
- 发送窗口 $W_T<= 2^n-1$
- 限制发送窗口，是为了在 ACK 丢失、帧超时重传、序号循环使用的情况下，让接收方仍然能区分“旧帧”和“新帧”
- 利用率: $U = \frac{nT_D}{T_D+RTT+T_A}$
- 序号比特数相同情况下, GBN 窗口更大, 理论传输效率更高
# 选择重传
- 发送方连续发送多个数据帧, 接收方接收或缓存乱序帧; 帧出错则重传对应帧
- 发送窗口 与 接收窗口 之和小于等于序号和 $W_T + W_R <= 2^n$ (GBN也满足这条)
- 利用率: $U = \frac{nT_D}{T_D+RTT+T_A}$
