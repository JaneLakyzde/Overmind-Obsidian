# 校验码的基本概念
- **码距** 也叫海明距离, 对应两个长度相同的码字之间, 对应不同二进制位的数量
- **编码集的码距** 编码集中的最小码距, 决定了其检错纠错的能力

| 码距(d)、检错(e)、纠错(t)的关系             | 检错能力、纠错能力      |
| -------------------------------- | -------------- |
| $d \geq e + 1$                   | 可检测e个误码        |
| $d\geq 2t + 1$                   | 可纠正t个误码        |
| $d \geq e + t + 1$  且 $e \geq t$ | 可检测e个误码并纠正t个误码 |
`码距为4, 则可检错3位, 纠错1位, 同时检错2位纠错1位`

# 奇偶校验
- **奇校验**: 增加一位校验数据, 使得码字中 1 的个数为奇数
- **偶校验**: 增加一位校验数据, 使得码字中 1 的个数为偶数
	通过奇偶限定, 剔除比特一数量非奇/偶的编码, 将编码集的码距限定为 2
	只能检测出一位误码
	在简单场景中使用
	硬件实现上, 偶校验更快速: 将原始数据逐位异或, 得到的值应该等于偶校验码

# 海明校验
原始数据中插入若干校验位形成海明校验码, 每个校验位对应一个校验组, 而每个数据位都位于两个或以上校验组中, 可以实现简单纠错, 以下为可纠错1位的海明校验码(码距为3)
- r 位校验位以及 m 位原始数据, 可能出错的位置共有 `m+r` 个，校验位组成的指错字（syndrome）有 `2^r-1` 种非零状态可以用来指示这些出错位置。
- **海明不等式**: `m + r <= 2^r - 1` 原始数据位数越大, 编码效率越高, 适用于存储器设备
- 校验位依次存放在标号为2的整数次幂的位置: 1、2、4、8...
- 分配方式:
	如 3 = 2 + 1, 则第三位的数据属于第一、二校验组
	
	应试分配法: 
		对编号为 `i` 的校验位，从第 `i` 位开始，连续选 `i` 位，再跳过 `i` 位，如此反复，选中的位即属于该校验组
		`如P3对应第三组为 H4 H5 H6 H7 H12 H13 H14 H15`
		
	编码时:
		将同组的所有**数据位**异或，结果填入该校验位，使得最终整个组（包含校验位）的异或和为 0 (偶校验)
		
	接收端对每个校验组重新计算偶校验：
		将组内**校验位及所有数据位**全部异或，得到该组的校验结果位。  
		将所有组的校验结果位按校验位权重 (如 $G_8G_4G_2G_1$ 排列成一个二进制数)
	- 若为 0，则无错；
	- 若不为 0，则该值直接指示出错的位号，将其取反即可纠错。
	
	主要用于计算机内部存储器的纠错码, 计算机网络数据链路层一般使用 CRC 进行检错
	网络层一般使用16位因特网检验和校验IP分组首部进行检错
	传输层一般使用16位因特网检验和校验整个UDP/TCP报文
	IPv6取消了首部校验和以便快速转发

# 循环冗余校验 
`CRC Cyclic Redundancy Check` 
计算出的余数（即 CRC 校验码/FCS）的位数，等于生成多项式的最高次数
	CRC-32 通常占4个字节
数据链路层主要采用循环冗余校验码, 因为现实中常为多位多比特突发性误码
计算要点在于: 多项式二进制模二除法, 余数为零则表示没有错误
- 前提: 收发双方先约定好同一个生成多项式, 将其转化为二进制格式
- 发送方:
	1. 在原始数据后面补零, 个数等于多项式的最高次数
	2. 将生成多项式 $G(x)$ 的各项系数作为除数
		进行模二除法（逐位进行**异或**运算，不产生进位/借位）
	3. 最终在余数前补零与多项式最高次数对齐

- 接收方: 
	1. 将接受到的数据作为被除数, 除以同一个除数
	2. 进行二进制模二除法, 逐位异或
	3. 若余数为零, 则表明无误码. 

- 注意事项: 
	1. 生成多项式必须包含常数项 1
	2. CRC 只能检测错误，不能纠错
		一旦余数不为 0，则丢弃该帧，依靠重传机制（ARQ）来保障正确性
	3. 使用高速硬件进行封装, 解包
	4. 多项式最高次数为4, 则被除数末尾加4个零, 余数补齐到4, 除数为5位

# 因特网检验和

-  **应用范围:** 
- IP层: 仅校验IP分组首部
	IPv6 修改Hop Limit后，都要重新计算整个首部的校验和
	取消了首部校验和以便快速转发
	
- 传输层: 校验整个TCP/UDP报文段（TCP必选，UDP可选）
	
	IP首部、TCP首部、UDP首部中都包含有一个 16bit 的首部检验和字段
	
- **算法**：16位**反码算术求和 + 按位取反**
	TCP/UDP 中需要额外添加伪首部后再进行计算
	
- **计算过程**：
    
    1. **分块**：将待校验的数据看作一串**16位字**（Word）。
        - IP首部（长度4字节倍数）：无需补零。
        - TCP/UDP数据：若字节数为奇数，**末尾补一个字节0**以对齐。
		
    2. **求和**：将每个16位字进行16位加法，若产生**进位（Carry）**，则将进位循环加到**最低位**。
        
    3. **取反**：对最终结果取反，填入检验和字段。
        
- **伪首部**：TCP/UDP计算时，需在报文前增加12字节的虚拟首部（不发送）：`源IP(4) + 目的IP(4) + 0(1) + 协议(1) + TCP/UDP长度(2)`。
    
- **校验**：接收方将包括“校验和”字段在内的所有16位字相加，结果应为 **0xFFFF**（全1）。
