# [[弗林分类法]]：

通过**指令流（Instruction Stream）** 与 **数据流（Data Stream）** 的数量组合，将计算机分为四类。属于[[多处理器]]概念

|分类|全称|特点|典型实例|现代适用性|
|---|---|---|---|---|
|SISD|Single Instruction, Single Data|顺序执行，单指令流处理单数据流|传统单核CPU（如早期x86）|基础模型，现代CPU单线程模式|
|SIMD|Single Instruction, Multiple Data|同指令并行处理多数据|GPU（CUDA核心）、Intel AVX/SSE、向量处理器（Cray-1）|极高：AI训练、图像/视频处理核心|
|MISD|Multiple Instruction, Single Data|多指令处理同一数据|理论模型；航天容错系统（多算法验证同一输入）|极低：学术争议大，无纯粹商用实现|
|MIMD|Multiple Instruction, Multiple Data|多指令流+多数据流，完全并行|多核CPU、服务器集群、分布式系统（Hadoop）|极高：现代计算主流（云计算、超算）|

### ① 控制流驱动 
(Control Flow Driven)，[[05_CS/001_计算机组成原理/冯诺依曼机]]，SISD

- **含义**：程序的执行顺序由**程序计数器（PC）**指定的指令序列决定。
    
- **逻辑**：CPU 按照指令在存储器中的先后顺序（或跳转指令指定的地址）一条接一条地取出并执行。只有前一条指令执行完（或达到特定阶段），下一条指令才会开始。
    
- **特点**：数据的处理是被动的，必须等待“指令”下达命令。
    

### ② 多指令多数据流
(Multiple Instruction Multiple Data)，MIMD

- **含义**：这是 **Flynn 分类法**中的最高级形式。指计算机系统中有多个独立的处理器，每个处理器执行不同的指令序列，处理不同的数据集。
    
- **场景**：多核 CPU、多处理器系统。
    
- **特点**：强调**并行性**。

# 类似概念：
### ③ 微程序控制方式 
(Micro-program Control)

- **含义**：这是一种**控制器（CU）的实现技术**。它将每一条机器指令拆解成一系列更小的“微指令”，存放在 CPU 内部的控制存储器（CM）中。
    
- **逻辑**：执行一条指令 = 运行一段微程序。
    
- **特点**：规整性好，便于修改和扩充指令集，但速度比硬布线控制慢。
    

### ④ 数据流驱动方式 
(Data Flow Driven)

- **含义**：与控制流相反。指令的执行顺序不取决于 PC，而是取决于**操作数是否准备就绪**。
    
- **逻辑**：只要一条指令所需的全部操作数都到齐了，这条指令就立即进入执行状态。
    
- **特点**：理论上具有极高的并行性，不设 PC，但在实际通用计算机设计中极难实现（主要用于特种巨型机）。

# 3. 综合对比表

|**概念**|**维度**|**冯·诺依曼机属性**|**考研常考点**|
|---|---|---|---|
|**控制流驱动**|**驱动方式**|**是（核心属性）**|PC 的自动加 1 与跳转。|
|**微程序控制**|**实现技术**|**可选（后期改进）**|控制存储器（CM）与微指令。|
|**多指令多数据**|**并行等级**|**否（经典冯氏为单流）**|多核处理器、共享存储模型。|
|**数据流驱动**|**驱动方式**|**否（与其对立）**|非冯·诺依曼架构的代表。|

|维度|微程序控制|数据流驱动|
|---|---|---|
|所属层次|控制器内部实现技术|整体计算范式|
|架构归属|冯·诺依曼体系内优化|非冯·诺依曼替代模型|
|核心问题|“如何生成控制信号？”|“指令何时该执行？”|
|依赖要素|程序计数器（PC）、指令流|数据令牌、数据依赖图|
|并行性|无（顺序执行微指令）|天然高并行|
|现代角色|CPU内部实现细节（常与硬布线混合）|思想渗透至GPU/编译器/框架，独立硬件已少见|
