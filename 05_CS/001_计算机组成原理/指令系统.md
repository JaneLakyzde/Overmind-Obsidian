# ISA 指令集体系结构 

ISA (Instruction Set Architecture) 是硬件和软件的交界面。

- **对程序员可见（不透明）：** 各种通用寄存器（GPR）、程序计数器（PC）、程序状态字寄存器（PSW/标志寄存器）、主存地址。
- **对程序员不可见（[[透明性]]）：** 指令寄存器（IR）、存储器地址寄存器（MAR）、存储器数据寄存器（MDR）、Cache、微程序。
    

**主要包括：**

1. 指令格式、寻址方式（绝对重点）
2. 操作数类型（如整型、浮点型等）
3. 寄存器组织（可见寄存器的种类和数量）
4. 指令控制方式（执行顺序与控制流）

# 指令格式

一条指令 = **操作码（Opcode）** + **地址码（Address）**。
操作码决定“做什么”，地址码决定“对谁做”。
通常在[[指令周期#2.1 取指周期]]中取的二进制串就是指令

## 按地址码数目分类

### 1. 零地址指令

- **概念：** 指令字中只有操作码，没有地址码。
- **情况 A：不需要操作数的指令**。例如空操作（NOP）、停机（HALT）、关中断（CLI）等。
    - **访存次数：** **1次**（仅取指令，不访存取操作数）。
        
- **情况 B：堆栈计算机的具体运算实现**。操作数隐含在栈顶和次栈顶。
    -  假如是加法（$Top + (Top-1) \to Top$），若栈在内存中，共需 **4次访存**：
        1. 取指令
        2. 栈顶弹栈取操作数1
        3. 次栈顶弹栈取操作数2
        4. 压栈存结果

### 2. 一地址指令

- **情况 A：单操作数指令**。如加1（INC）、减1（DEC）、取反。
    -  $OP(A_1) \to A_1$。
    - **访存次数：** 3次（取指令、读操作数、写回结果）。
        
- **情况 B：隐含双操作数指令**。另一个操作数隐含在累加器（ACC）中。
    -  $(ACC) OP (A_1) \to ACC$。        
    - **访存次数：** 2次（取指令、读操作数$A_1$。结果写回寄存器ACC，不访存内存）。
        

### 3. 二地址指令（最常见）

- **执行过程：** $(A_1) OP (A_2) \to A_1$ （将结果存入第一个地址）。
- **难点扩展（常考选择/综合）：** 根据操作数的物理位置，分为三种类型：
    1. **SS（存储器-存储器）型：** 两个操作数都在内存，访存次数最多（取指1+读A1+读A2+写A1 = 4次）。
    2. **RS（寄存器-存储器）型：** 访存次数中等（取指1+读内存操作数1 = 2次，假设结果写回寄存器）。
    3. **RR（寄存器-寄存器）型：** 执行最快，除取指令外不访存内存。
        

### 4. 三地址指令

-  $(A_1) OP (A_2) \to A_3$。
- **优势：** 运算结果不会破坏原操作数。
- **访存次数：** 4次（取指1 + 读A1 + 读A2 + 写A3）。

### 5. 四地址指令

-  $(A_1) OP (A_2) \to A_3$，下一条指令地址为 $A_4$ 
- **访存次数：** 4次（取指1 + 读A1 + 读A2 + 写A3）
- **特点：** 取指令时已经取了下一条指令的地址，**不需要再次修改PC的值**。正常情况下PC会自动加1，但四地址指令直接用 $A_4$ 替换PC的值

# 操作码格式

## 1. 定长操作码

- **特点：** 所有指令的操作码长度相同。
- **优点：** 硬件译码设计简单，速度快，多用于 **RISC（精简指令集）**。

## 2. 可变长/扩展操作码

- **特点：** 操作码的长度随地址码数量的减少而增加。多用于 **CISC（复杂指令集）**。
- **核心原则（重要）：** **短操作码一定不能是长操作码的前缀！**（类[[哈夫曼编码]]）。
    

> **💡 难点扩展：扩展操作码计算公式**
> 
> 假设指令字长为固定长度，地址码长度为 $n$ 位。
> 
> 上一级指令留出了 $x$ 种状态用于扩展，那么下一级（减少一个地址码）可以增加的指令条数为：**$x \times 2^n$**。
> 
> _考研经典题型口诀：_ **“留几乘几”**。如果二地址指令有15条，占用了4位操作码（共16种状态），留了1种状态（1111）给一地址指令扩展。若地址码长6位，则一地址指令最多可以有 $1 \times 2^6 = 64$ 条。

# 按类型分类

## 1. 数据传送类

-  `LOAD` (读内存到寄存器), `STORE` (写寄存器到内存), `MOV` (寄存器之间传送)
- **注意：** 数据传送类指令通常**不修改**标志寄存器（PSW）的状态

## 2. 算术与逻辑运算类

- `ADD`, `SUB`, `AND`, `OR`, `XOR`。
- 这类指令执行后，一定会更新 **PSW（程序状态字）**，如进位标志(CF)、零标志(ZF)、符号标志(SF)、溢出标志(OF)。后续的条件转移指令就是看着这些标志位来执行的。

## 3. [[移位运算]]操作类

- **分类：** 算术移位、逻辑移位（无符号，一律补0）、循环移位（带进位位循环 vs 不带进位位循环）。
- **应用：** 移位操作常用于实现乘除法的底层优化。

## 4. 转移操作/程序控制类

这是改变程序执行顺序的指令，会直接修改 **PC（程序计数器）** 的值。

- **无条件转移：** `JMP`。
- **条件转移：** `JZ` (Zero), `JC` (Carry) 等，依赖前面ALU运算留下的PSW标志。
- **调用与返回（CALL / RETURN）：**
    - **与JMP的本质区别（常考大题）：** `CALL` 不仅要跳转，还必须**保存返回地址**（通常压入堆栈），而 `JMP` 去了就不回来了。`RETURN` 则是从堆栈弹出地址放回 PC。

## 5. 输入输出（I/O）操作

- **主要功能：** CPU与外部设备端口之间的数据传送。
- 要区分系统采用的是 **统一编址**（I/O端口当成内存地址，用普通LOAD/STORE指令）还是 **独立编址**（有专门的IN/OUT指令）。

# RISC 和 CISC
| 对比维度       | RISC（精简指令集）           | CISC（复杂指令集）   |
| ---------- | --------------------- | ------------- |
| **设计思想**   | 简化指令系统，提高执行效率         | 增强指令功能，减少指令数量 |
| **指令数量**   | 少而精                   | 多而复杂          |
| **指令功能**   | 单一、简单                 | 一条指令可完成复杂操作   |
| **指令长度**   | 通常固定长度                | 通常可变长度        |
| **指令格式**   | 规整、统一                 | 多样、不规则        |
| **寻址方式**   | 较少                    | 丰富            |
| **访存方式**   | Load/Store（仅特定指令访存）   | 多数指令可直接访问内存   |
| **寄存器数量**  | 较多通用寄存器               | 相对较少          |
| **执行方式**   | 多条简单指令完成任务            | 少量复杂指令完成任务    |
| **流水线支持**  | 非常适合（但不是必须）           | 实现较复杂（但现代也支持） |
| **硬件复杂度**  | 较低                    | 较高            |
| **编译器依赖**  | 高（依赖编译器优化）            | 相对较低          |
| **代码长度**   | 较长（指令多）               | 较短（指令功能强）     |
| **执行速度特点** | 单条指令快、整体效率高           | 单条指令慢但功能强     |
| **典型架构**   | ARM、MIPS、RISC-V、SPARC | x86、VAX       |
