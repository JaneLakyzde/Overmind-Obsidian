# [[中断的分类]]:
在大多数情况下, 中断可以理解为外中断

| 类型          | 子类            | 触发原因     | 是否与当前指令相关 | 能否返回     | 典型例子             |     |
| ----------- | ------------- | -------- | --------- | -------- | ---------------- | --- |
| **外中断**     | 可屏蔽中断         | I/O 设备完成 | ❌ 无关      | ✅        | 键盘输入、磁盘 I/O、时钟中断 |     |
|             | 不可屏蔽中断（NMI）   | 严重硬件故障   | ❌ 无关      | ✅（但可能关机） | 电源故障、内存错误        |     |
| **内中断（异常）** | **Trap（陷阱）**  | 程序主动请求   | ✅ 相关      | ✅（下一条指令） | **系统调用**、断点      |     |
|             | **Fault（故障）** | 可恢复错误    | ✅ 相关      | ✅（当前指令）  | **缺页中断**、除零      |     |
|             | **Abort（终止）** | 严重不可恢复错误 | ✅ 相关      | ❌        | 非法指令、硬件故障        |     |
# 中断工作流
## 1. 中断请求

1. 中断源: 引起中断的事件或设备
	
2. 中断请求标记触发器:
- 保存中断请求状态
- 当某个中断源提出请求后，将对应触发器置位
- CPU 在合适时机查询这些标记，决定是否响应中断
	
	INTR
- 可屏蔽中断请求引脚 Interrupt Request 也叫中断请求触发器
-  ==外部设备的中断请求都是可屏蔽中断!==
- 外部设备通过它向 CPU 发出中断请求, 到 CPU 中的中断请求寄存器 IRR 中排队
- 是否响应受 **IF** 控制
	
	NMI Non-Maskable Interrupt
- **不可屏蔽中断请求引脚**
- 不受 IF 控制
- 常用于电源故障、存储器奇偶校验错等紧急事件
	
	INTA Interrupt Acknolwedge
- **中断响应信号**
- CPU 响应中断后，向中断控制器发出的应答信号
- 用于通知中断源：CPU 已经接受中断，请提供中断类型号等信息
	
	IF Interrupt Flag
- 中断允许触发器, 用来控制**可屏蔽中断**是否允许被 CPU 响应
- `IF=1`：开中断，可响应 INTR
- `IF=0`：关中断，不响应 INTR
- **对异常和 NMI 无效**

## 2. 中断响应优先级

⚠️ 响应优先级 和 处理优先级不同:
	处理优先级与屏蔽字有关, 主要决定嵌套中断里, 是否允许更高优先级中断打断

不可屏蔽中断 ＞ 内部异常 ＞ 可屏蔽外中断
硬件故障 ＞ 软件中断
DMA 请求 ＞ 普通 I/O 中断
高速设备 ＞ 低速设备; 输入设备 ＞ 输出设备 ; 实时设备 ＞ 普通设备
## 3. CPU响应中断的条件

3.1 有中断请求
- 至少有一个中断源发出中断请求
- 对应中断请求标记为 1

3.2 CPU 允许中断
- 对于**可屏蔽中断**，要求 `IF=1` 开中断
- **异常**和**不可屏蔽中断 NMI**不受 IF 限制

3.3 CPU 只在一条指令的最后一个机器周期执行结束后才检查外部中断请求
- 一般在**当前指令执行结束后**，CPU 才响应外中断
- 异常 在当前指令执行过程中就会直接触发, 属于同步事件
- DMA 请求可以在任意机器周期结束时, 因为DMA只需要总线控制权, 不需要保存CPU现场

## 4. 中断隐指令

隐指令不是代码, 而是由 ==硬件自动完成的一系列操作== 实现的中断响应过程

当 CPU 决定响应中断后，硬件会自动执行以下三步：

1. **关中断:** 将 `IF` 置 0。这是为了防止在保存断点和现场的过程中，被新的中断打断导致数据混乱。

2. **保存断点:** 将当前的程序计数器 `PC`和 `PSW` 压入堆栈保存    

3. **引出中断服务程序:** 硬件通过数据总线读取外设发来的中断类型号，去**中断向量表**中查找对应的中断服务程序的入口地址，并将其赋值给 `PC`

中断向量即硬件查询法.非中断向量即[[中断的分类|软件查询法]], 中断向量就是对应的中断服务程序入口地址

## 5. 中断服务程序

进入中断服务程序后，由软件（指令）完成具体工作，流程如下：

1. **保护现场:** 将 CPU 中的==通用寄存器==内容压栈保存。
	注意：保护断点是硬件做的，保护现场是软件做的！
	
	2. **开中断**: (如果系统允许多重中断)
	此时需要将 `IF` 重新置 1，允许更高优先级的中断打断自己。
	如果只允许单重中断，此步省略。
    
3. **中断事件处理:** 执行实质性的 I/O 数据交换或故障处理程序。
    
	4. **关中断 (可选):** 在恢复现场前，必须保证恢复过程不被打断
	（如果第 2 步开了中断，这里必须关掉）。
    
5. **恢复现场:** 将之前压栈的通用寄存器内容弹出恢复。
    
6. **开中断 + 中断返回:** 执行 `IRET` (Interrupt Return) 特权指令。这条指令会从栈中弹出原 `PC` 和 `PSW`，同时自动开中断，回到主程序被打断的地方继续执行。

## 6. 多重中断

多重中断（中断嵌套）允许 CPU 在执行中断服务程序时，响应更高优先级的请求。
### 多重中断的条件:

1、中断服务程序在保存现场后立刻设置开中断
2、优先级别高的中断源有权中断级别低的

###  [[中断优先级]]
这是一个由软件控制的“逻辑优先级”，与硬件固定的“响应优先级”不同。

- **响应优先级（硬件固定）：**
    
    - CPU **响应**中断请求的先后顺序。
    - 由硬件排队器（如中断控制器 8259A）决定。
        
- **处理优先级（软件可改）：**
    
    - CPU **处理完成**中断的先后顺序。
    - 通过**中断屏蔽技术**动态调整。
	
- 顺序: 先根据响应优先级响应瞬间处理防止数据丢失, 再根据处理优先级处理

## 7. 中断屏蔽技术
### 屏蔽字

每个中断源都有一个对应的屏蔽字。当 CPU 进入该中断源的服务程序时，会将此屏蔽字送入屏蔽寄存器。

- **设置原则：**
    
    - **屏蔽自己：** 屏蔽字中对应自身位必须为 `1`。
        
    - **屏蔽低级：** 将所有处理优先级低于自己的中断位设为 `1`。
        
    - **开放高级：** 将所有处理优先级高于自己的中断位设为 `0`。
