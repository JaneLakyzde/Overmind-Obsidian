在计算机[[中断的处理]]系统中，面对多外设并发请求，为了解决“先理谁”和“先干完谁”的问题，引入了两种核心优先级概念：

## 1. 响应优先级
- **定义**：CPU**响应**各中断源请求的先后顺序。当多个中断源在**同一时刻**同时提出请求时，CPU通过硬件排队器瞬间决定的首先进入哪一个中断源的服务程序。
    
- **决定因素**：**纯硬件电路**决定（如链式查询电路、独立请求排队器等）。
    
- **特性**：**固定不可变**。板卡电路焊接好后，硬件响应顺序即锁死。
    

## 2. 处理优先级

- **定义**：CPU**实际执行完**各中断服务程序的先后顺序。在允许中断嵌套（多重中断）的系统中，它决定了当前正在执行的中断能否被新来的中断“插队”。
    
- **决定因素**：**软件**决定（通过程序员或操作系统改写**中断屏蔽字**）。
    
- **特性**：**动态可变**。可以通过程序运行时动态修改屏蔽寄存器的值来随时调整。
    

---

## 3. 核心区别对比表

|**维度**|**响应优先级（硬件排队）**|**处理优先级（软件屏蔽）**|
|---|---|---|
|**本质关注**|谁先**进门**（进入中断入口）|谁先**干完活**（完成服务程序）|
|**控制机制**|硬件排队器 / 优先编码器|中断屏蔽寄存器（中断屏蔽字）|
|**灵活度**|静态固定，无法修改|动态灵活，程序可控|
|**生效时机**|**中断响应阶段**（指令周期结束时）|**中断服务阶段**（执行服务程序时）|
|**设计目的**|解决突发**硬件物理冲突**，防数据丢失。|解决宏观**业务紧急度调度**，保证关键任务。|

---

## 4. 中断屏蔽字

要实现处理优先级的改变，必须依赖**中断屏蔽字**。

- **基本原理**：每个中断源都有一个对应长度为中断源总数的屏蔽字。
    
    - `1` 表示**屏蔽**该中断源（即老子不让你插队）。
        
    - `0` 表示**开放**该中断源（即你可以来插队）。
        
- **设置规律**：
    
    1. 自身对应的位通常设为 `1`（自己不能插自己的队）。
        
    2. 处理优先级**高于**自己的中断源对应位设为 `0`（允许它们插队）。
        
    3. 处理优先级**低于**自己的中断源对应位设为 `1`（拒绝它们插队）。

## 5. 具体实例
-  第一步：外设硬件缓存阶段（数据处于危险期）
	
	- **发生什么**：网线上的电信号转为数字信号，进入网卡芯片内部的**数据缓冲寄存器（DBR）**。
    
	- **硬件状态**：网卡内部的“完成触发器”置 1（D = 1，表示数据已就绪）。
    
	- **危险性**：此时数据非常危险。网卡芯片的内部缓存极小，如果下一个数据包在几微秒内到达，而旧数据还没被拿走，就会发生**硬件溢出（Overrun）**，数据直接被覆盖丢失。
    
- 第二步：举手请求与 CPU 抽查
	
	- **发生什么**：网卡的中断请求触发器置 1（INTR = 1），向系统总线发射中断信号。
    
	- **CPU 动作**：CPU 在执行当前指令的**最后一个时钟周期**（指令周期的结束阶段），硬件电路会自动去检测 INTR 引脚的电平。
    
	
- 第三步：中断响应（黄金分水岭）
	
	- **发生什么**：CPU 发现有高级别中断，决定“响应”。
    
	- **硬件隐指令**：CPU 硬件自动完成三件事：
    
    1. 关中断（防止别人打扰）。
        
    2. 保护断点（把当前的 PC 寄存器压栈）。
        
    3. **根据设备编码器找到网卡的中断向量地址（入口地址），强制跳转。**
        
	- _注意：到这一步，数据依然在网卡的小邮箱里，但 CPU 的指针已经到了网卡服务程序的门口。_
    
- 第四步：数据大抢救（不丢数据的核心环节！）
	
	- **进入软件阶段**：CPU 开始执行网卡的中断服务程序（ISR）。
    
	- **第一要务**：程序通常会先用几条普通的汇编指令（如 `PUSH`）保护现场寄存器，紧接着，**一定会执行一条数据搬运指令**（例如 x86 汇编中的 `IN` 指令，或者操作内存映射的 `MOV` 指令）：
    
    > `IN EAX, dx` （从网卡的数据端口 DX 中，把数据读入 CPU 寄存器 EAX，随后立刻 `MOV` 写入主存 RAM）。
    
	- **物理转移**：数据在这一瞬间，通过数据总线，**从“外设的危急缓存”被复制到了“宽敞安全的主内存（RAM）”中**。
    
	
- 第五步：外设缓存释放
	
	- **硬件联动**：当 CPU 执行 `IN` 指令从网卡读取数据的同时，网卡芯片的硬件电路会受到一个“读盘效应”的触发，**自动将完成触发器清零（D = 0）**。
    
	- **结果**：网卡的“小邮箱”瞬间空了。网卡重新恢复到清白状态，可以张开双臂迎接下一个从网线上飞奔而来的网络数据包。
    
	
- 第六步：后续业务处理（可以慢慢来）
	
	- 现在，刚刚收到的数据包已经躺在 RAM 的缓冲区（比如操作系统的内核缓冲区）里了。
    
	- 中断服务程序此时可以安心地“开中断”，甚至把这个数据包交给操作系统的网络协议栈（IP/TCP层）去慢慢解析、校验、最后传递给你的 QQ 或微信。哪怕后面解析业务花了 1 毫秒，网卡也绝对不会丢失后续的数据，因为它的硬件缓存早就被清空了。
