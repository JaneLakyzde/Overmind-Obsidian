CPU 在读取数据的时候, 大部分情况下都是只会从 Cache 中读, Cache 是主存与 CPU 之间的必经之路

局部性原理:空间/时间
Cache块 也称为 Cache行

# 映射 Mapping

Cache 行具体结构:
`有效位 + 脏位 + 替换控制位 + 标记位 + 数据 + 校验位(可选)`
脏位 - 回写法
替换控制位 - LRU / LFU


### 直接映射
- 主存中的一个块只能映射到 Cache 中的唯一一行, 只需要一个比较器
- 替换位置固定，无需替换算法  
- 实现简单，但冲突未命中较多
- `主存地址 = 标记位 + Cache 行号 + 块内地址`
	$\text{块内地址位数} = \log_2 {每块大小}$
	$\text{行号位数} = \log_2{Cache行数}$
	$\text{标记位位数}=\log_2\left(\frac{\text{主存总块数}}{\text{Cache行数}}\right)$
	%%行号对应同一 Cache 对应的主存块个数, 块内地址对应块的大小%%
	
### 全相联映射
- 性能好,开销大,常用于[[相联存储器]], 需要为每一个行设置一个比较器
- `主存地址 = 标记位 + 块内地址`
	$\text{块内地址位数} = \log_2 {每块大小}$
	$\text{标记位位数}=\log_2(\text{主存总块数})$
	
### 组相联映射
- 引入标记位 组号 组内全相联
- 每组中有`n`个 Cache 行, 就称为` n 路组相联`
- `主存地址 = 标记位 + 组号 + 块内地址
	$\text{块内地址位数} = \log_2{每块大小}$
	$\text{组号位数} = \log_2 \frac{Cache行数}{每组行数}$ %%从这么多组里, 确定哪一组%%
	$\text{标记位位数}=\log_2\left(\frac{\text{主存总块数}}{\text{Cache组数}}\right)$
	%%标记位 = 每个Cache块数对应主存个数取2对数,组号对应分组个数取 2 的对数%%

总的来说:
$$\text{标记位位数}=\log_2(\text{某一Cache行或组所对应的主存块数})$$

# 一致性问题

### 写操作命中
即要修改的内容在Cache中时:
- 全写法:
	Cache和主存中的内容一起改写, 不用将Cache写回主存. 强调数据一致性
	写缓冲 Write Buffer: 直接写
	%%全写法本来每次都是直接写主存的, 若写不命中还要调入主存,多次一举.%%
	
- 回写法: 
	只修改Cache, 并只将修改过的 Cache 写回主存. 强调效率
	%%强调数据留在 Cache 中反复修改, 所以写不命中时, 干脆把块调入 Cache 中好了%%

### 写操作不命中时:
- 写分配法: 修改主存, 并将对应块调入 Cache 中.
- 非写分配法: 只更新主存单元,不掉入Cache.

# Cache 缺失的时钟周期损失
### 同步总线传输

**同步传输** (Synchronous Bus Transfer)的核心在于一个统一的时钟信号 ($\text{CLK}$)**。
- **统一节拍**：总线上所有的设备（CPU、内存、I/O）都看着同一个“指挥棒”动作。所有的地址信号、数据信号、控制信号的发出和接收，都发生在时钟的上升沿或下降沿。
- **优点**：协议简单，不需要复杂的“握手”（Handshaking）过程，传输速度快。
	在计算时间时，同步总线的一个操作通常占用整数个时钟周期。
    

### 突发传输

 突发传输 (Burst Transfer) 是为了解决“内存速度跟不上 CPU”而设计的黑科技。它的核心思想是：**“只送一次地址，连续传一整块数据。”**

通常的访问模式是：

1. **传地址 A** $\rightarrow$ 等待 $\rightarrow$ **读数据 A**
2. **传地址 A+1** $\rightarrow$ 等待 $\rightarrow$ **读数据 A+1**
    

而**突发传输**改变了节奏:
- **发起始地址 A** $\rightarrow$ **漫长的等待（首字延迟）** $\rightarrow$ **读数据 A** $\rightarrow$ **读数据 A+1** $\rightarrow$ **读数据 A+2** $\rightarrow$ **读数据 A+3**..
