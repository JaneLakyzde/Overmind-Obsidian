## 一、 定义


通道是一种专用的大型 I/O 处理机。它可以被看作是一个被“阉割”了算术逻辑运算功能，但强化了数据搬运和外设控制能力的“小 CPU”, 是[[DMA]]加强版

- 中断方式： 每传一个字，主 CPU 都要被打断一次，主 CPU 太累。
    
- [[DMA]] 方式： 实现了数据块的硬件自动传输，但主 CPU 每次只能让 DMA 传一个连续的数据块。传完一块，主 CPU 就得重新设置 DMA 寄存器。如果系统挂载了成百上千个外设，频繁的 DMA 初始化和中断依然会拖垮主 CPU。**
    
- 通道方式： 主 CPU 只需要下达一条宏观指令（比如“你去把这批设备的读写任务全干了”），通道就能独立从内存中读取一系列指令（通道程序），控制多个设备完成多块、不连续的数据传输。主 CPU 彻底成了“甩手掌柜”。
    

## 二、 核心特征与组成

1. 拥有独立的指令系统： 通道能执行自己的机器指令，这些指令被称为通道指令（CCW, Channel Command Word）。
    
2. 执行通道程序： 若干条通道指令可以组成一段通道程序，存放在主存中。通道通过执行这些程序来控制外设。
    
3. 共享主存： 通道和主 CPU 共享主存资源。通道必须有能力通过竞争获取总线控制权。
    

## 三、 通道的三大分类

根据信息交换方式和连接设备的类型，通道分为三种

| 核心考点辨析 | 字节多路通道             | 选择通道                     | 数组多路通道                   |
| ------ | ------------------ | ------------------------ | ------------------------ |
| 外设速度   | 中低速            | 高速                   | 高速                   |
| 传送单位   | 字节             | 数据块                  | 数据块                  |
| 程序执行   | 各设备程序交叉执行      | 逐个设备程序串行执行           | 各设备程序交叉执行            |
| 时间片分配  | 字节级分时              | 整个程序独占                   | 块级分时 / 间隙复用              |
| 关键特征   | 宏观并行，微观逐个字节交替。 | 某台外设一旦选中，整个传输期间独占通道，死等外设 | 充分利用高速外设通道等控制间隙，去伺候其他设备。 |
| 利用率    | 高                  | 低（被准备时间榨干）           | 极高（兼顾高速与多路）          |
### 1. 字节多路通道

- 连接对象： 大量低速设备（如键盘、鼠标、打印机）。
    
- 工作方式： 采用时间分多路复用（分时）的原理。它包含多个子通道，每个子通道连接一个设备。通道像“发牌”一样，轮流为各个设备传送一个字节。
    
- 特点： 虽然整体看来通道在同时为多个设备服务，但微观上，它是在各个设备间高速切换。
    

### 2. 选择通道

- 连接对象： 少数高速设备（如磁盘、磁带机）。
    
- 工作方式： 在一段时间内，通道独占性地分配给某一台高速设备，直到该设备的整个数据块全部传送完毕，才释放通道给下一个设备使用。
    
- 特点： 数据传输率极高。但利用率低，因为当高速设备在进行机械寻道（如磁盘转动找扇区，此时不传数据）时，通道只能闲置等待，其他设备也无法插队使用。
    

### 3. 数组多路通道

- 连接对象： 多个高速设备。
    
- 工作方式： 结合了前两者的优点。它允许多个高速设备交叉工作。当设备 A 在进行机械动作（寻道、不传数据）时，通道会立刻切换去服务设备 B 传送数据；当设备 A 准备好数据后，通道再切回来。每次传送的基本单位是一个数据块（数组）。
    
- 特点： 既有极高的数据传输率，又保持了极高的通道利用率。是现代大型机中最优秀的通道设计。
    

## 四、 通道的工作流程

一次完整的通道 I/O 流程，体现了主 CPU、通道、设备三者的协同：

1. 准备阶段 (OS 软件完成)： 操作系统在主存中编制好通道程序，并将第一条通道指令的地址存放在某个约定的内存单元或通道地址寄存器中。
    
2. 启动阶段 (主 CPU 完成)： 主 CPU 遇到 I/O 请求时，执行一条特权的 `启动 I/O (Start I/O)` 机器指令。这条指令的作用仅仅是“唤醒”通道，告诉它“你可以开始干活了”。主 CPU 随即继续执行其他程序。
    
3. 执行阶段 (通道硬件独立完成 ⭐)： 通道接管控制权。它通过查内存，取出通道指令并执行，向外设发出控制信号，并在外设和主存之间直接搬运数据。这个过程不需要主 CPU 任何干预。
    
4. 结束处理 (产生 I/O 中断)： 当通道程序执行完毕（或者中间遇到严重硬件故障），通道会向主 CPU 发出通道结束中断请求。主 CPU 响应中断，调出操作系统的中断服务程序来进行善后（比如唤醒因等待 I/O 而阻塞的进程）。

## 五、 通道 vs DMA


| 比较维度       | DMA 方式                                 | 通道方式                                   |
| -------------- | ------------------------------------------ | ------------------------------------------ |
| 智能程度 / 灵活性 | 低 (硬件逻辑)。只能执行单一的数据块传送，缺乏分支、逻辑判断能力。     | 高 (软硬结合)。能执行内存中的通道程序，具备强大的逻辑控制能力。      |
| 控制范围       | 一对一。一个 DMA 控制器通常只控制一台（或极少数）同类设备，只负责一次连续传输。 | 一对多。一个通道可以控制多台不同类型、不同速度的设备，执行复杂的批量 I/O 任务。 |

---

| 对比维度        | DMA 工作流程特征                 | 通道 工作流程特征                             |
| ----------- | -------------------------- | ------------------------------------- |
| CPU 怎么启动它？  | CPU 直接改写 DMAC 的硬件寄存器。      | CPU 执行 I/O 指令，提供 主存中的通道程序首地址。         |
| 数据的搬运依据？    | 靠 DMAC 内部的硬件计数器和状态机逻辑。     | 靠通道硬件去执行软件编写的通道程序                     |
| 对 CPU 的中断频率 | 每传完 一个数据块（Block） 中断一次 CPU。 | 整个 通道程序（可能包含多个数据块和多台设备） 结束后才中断一次 CPU。 |
| 总线控制方式      | 通过周期挪用或停止 CPU 的方式强行抢占总线。   | 通道本身就是主控部件，具有极高的自主总线控制和多路复用能力。        |
| 传输灵活性       | 极低。只能传连续内存地址的单个数据块。        | 极高。可以通过指令实现跳跃传输、复杂控制                  |
|             |                            |                                       |
