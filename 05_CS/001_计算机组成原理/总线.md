# 基本概念

- **分时**: 同一时刻只允许有一个部件向总线发送信息
- **共享**: 总线上可以挂接多个部件
- 主从设备: 主设备发送总线请求并获得总线控制权; 从设备只能响应主设备发送的各种命令
- 总线特性
	机械特性 (尺寸形状)
	电气特性 (传输方向和有效的电平范围)
	功能特性 (每根线的功能)
	时间特性 (信号和时序的关系)
# 分类
## 1. 按功能层次分类

1. **片内总线**: 芯片内部的总线
2. **系统总线**: 连接各个功能部件的总线
	
	数据总线: 数据、指令、中断信号, 双向传输, 位数反映一次能传输数据的位数
	地址总线: 数据的主存单元或I/O端口的地址, 单向传输, 位数反映最大寻址空间
	控制总线: 命令、反馈和定时信号, 单向传输, 控制信号与状态信号都是单向传输且相反
	
3.  **I/O 总线**: USB、PCI
4. **通信总线**: 也叫外部总线
## 2. 按时序控制分类

1. 同步总线: 按照时钟节拍进行规定的操作
2. 异步总线: 以信号握手的方式来协调各部件和设备之间的信息传输, 时序不固定
## 3. 按数据传输方式分类

1. 串行总线: 一条双向或两条单向, 长距离通信, 信号衰减小
2. 并行总线: 效率高, 稳定, 但是速度不一定更快 (工作频率受数据协调制约)
# 系统总线结构

### 1. 单总线结构

- **结构**：CPU、主存、所有的 I/O 设备都挂载在同**一组**系统总线（数据 + 地址 + 控制）上。
- **优点**：结构简单，成本低，易于接入新的设备。
- **缺点**：**总线带宽成为系统瓶颈**。同一时刻只能实现两个设备之间的数据传输，多部件竞争总线激烈，系统整体效率低。

### 2. 双总线结构

- 双总线结构有多种形式，最经典的是“主存总线 + I/O 总线”结构：
    - **主存总线**：专门用于 CPU 和主存之间的高速数据交换。
    - **I/O 总线**：用于连接各种 I/O 设备。两者通过**通道**（或总线控制器/桥接器）连接。
        
- **优点**：将低速的 I/O 设备从单总线上分离出来，缓解了系统总线的负荷，提高了 CPU 访问主存的速度。
- **缺点**：增加了硬件成本和控制复杂度。

### 3. 三总线结构

- **结构**：
    - **主存总线**：CPU 与主存之间。
    - **I/O 总线**：CPU 与各类中低速 I/O 设备之间。
    - **[[IO方式|DMA]] 总线 (直接内存访问总线)**：主存与高速 I/O 设备（如磁盘）之间。
        
- **优点**：高速 I/O 设备可以通过 DMA 总线直接访问主存，无需经过 CPU 介入，极大提升了系统并发工作能力和数据传输效率。
- **缺点**：系统架构最为复杂，成本最高。

# 总线性能指标计算


- **总线周期 ($T$)**：一次总线操作所需要的时间。通常包含若干个时钟周期。
- **总线工作频率 ($f$)**：总线周期的倒数，即 $f = 1 / T$。指一秒内传送几次数据。通常与时钟频率正相关
- **总线宽度 ($W$)**：数据总线的根数，通常用比特 (bit) 或字节 (Byte) 表示。
- **总线带宽 ($B$)**：总线的数据传输率，即单位时间内总线上可传输的数据量。

**计算公式**：

$$B = W \times f$$

_(注意：计算带宽时，总线宽度 $W$ 通常要换算成**字节 (Byte)**，即位数除以 8。频率 $f$ 用 MHz 时，带宽单位为 MB/s)_

注意 **[[DRAM 地址线复用]]本质上影响的是 寻址延迟 和 有效吞吐量 ，而不会改变系统理论上的 总线带宽**

# 总线事物

从请求总线到完成总线使用的完整操作序列称为一个总线事务。它描述了主设备和从设备之间一次完整的信息交换过程。

- 1. **请求阶段 (Request)**：主设备（如 CPU、DMA 控制器）需要使用总线时，向总线仲裁器（或总线控制器）发出“总线请求”信号。
    
- 2. **仲裁阶段 (Arbitration)**：总线仲裁器根据一定的优先级算法（如轮询、链式查询、独立请求等），决定将下一个总线使用权分配给哪个发出请求的主设备。一旦获准，主设备取得总线控制权。
    
- 3. **寻址阶段 (Addressing)**：取得控制权的主设备，通过**地址总线**发出本次要访问的从设备的内存地址或 I/O 端口地址，并通过**控制总线**发出相应的操作命令（如读/写命令）。从设备进行地址译码，确认自己被选中。
    
- 4. **传输阶段 (Transfer)**：主设备和从设备之间通过**数据总线**进行数据的单向或双向传输。这是总线事务的实质性阶段
	突发方式: 一组连着传; 非突发方式: 一个一个传
    
- 5. **释放阶段 (Release)**：数据传输完成（或发生错误）后，主设备撤销有关的控制信号和地址信号，让出总线使用权，以便其他设备能够继续使用总线。

# 总线定时
### 1. 同步定时方式

- **概念**：系统采用一个**统一的时钟信号**来协调发送和接收双方的传送定时关系。所有的操作都由统一的时钟节拍（通常是时钟的上升沿或下降沿）来控制。
- **特点**：规定明确、统一，控制逻辑简单。数据的传输速率较高。
- **缺点**：缺乏灵活性。总线周期的时间被固定死了，必须按照最慢的部件来设计时钟周期，否则慢速部件会跟不上。
- **适用场景**：总线长度较短、各部件存取时间比较接近的系统。
    

### 2. 异步定时方式 

- **概念**：没有统一的时钟，也没有固定的时间间隔，完全依靠双方相互制约的“握手”信号来实现定时控制。主设备提出请求（请求信号），从设备完成操作后给出应答（应答信号）。
    
- **分类**（根据请求和应答信号的撤销条件，分为三种互锁方式）：
    
    - **不互锁 (Non-interlocked)**：主设备发出“请求”，经过一段固定时间后自动撤销“请求”；从设备收到请求后发出“应答”，经过一段固定时间后自动撤销“应答”。双方互不等待确认，**最不可靠**。
    - **半互锁 (Half-interlocked)**：主设备发出“请求”，必须**收到从设备的“应答”后，才撤销“请求”**（有互锁）；但从设备的“应答”发出后，经过一段时间自动撤销，不关心主设备是否真的收到了（无互锁）。
    - **全互锁 (Fully-interlocked)**：主设备发出“请求”，必须**收到“应答”才撤销**；从设备发出“应答”，必须**获知主设备已经撤销了“请求”，才撤销自己的“应答”**。双方完全同步，**最可靠，但速度最慢**。
        
- **适用场景**：各部件速度差异较大的系统，或设备允许即插即用的 I/O 总线。
    

### 3. 半同步定时方式 

- **概念**：同步与异步的结合。它既保留了同步定时的**统一时钟**，又增加了一个**等待 (WAIT) 信号**。

- **工作原理**：通常情况下按同步时钟节拍工作；
	- 当主设备访问一个慢速从设备时，从设备如果来不及准备数据，就会发出 WAIT 信号。
	- 主设备检测到 WAIT 信号有效，就会在当前时钟周期结束后插入一个（或多个）等待周期，直到 WAIT 信号无效后再继续传输。

- **特点**：既有同步方式的高效，又有异步方式兼容不同速度设备的灵活性。
    

### 4. 分离式定时方式

- **概念**：将一个总线事务强行**劈成两个独立的子事务**。提高总线利用率、挖掘总线空闲潜力
    
- **工作原理**：    
    - **子事务1**：主设备 A 获取总线，向从设备 B 发送地址和命令，然后**立刻释放总线**。
    - **中间阶段**：从设备 B 在内部准备数据（比如读取磁盘）。这段时间**总线是空闲的**，其他设备可以借用总线。
    - **子事务2**：从设备 B 数据准备好后，B 临时变成主设备，主动申请总线控制权，将数据发送给 A。
        
- **特点**：    
    - **没有空闲等待时间**，各部件都在总线上“尽力而为”。
    - 两个子事务都只进行单向传输。
    - **总线利用率极高**，但控制逻辑最为复杂。
        
- **适用场景**：大型计算机系统、多处理器系统的高速总线。
