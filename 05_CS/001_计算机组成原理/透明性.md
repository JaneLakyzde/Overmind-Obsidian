程序员一般分为两种：“系统汇编程序员”和“应用程序员”

| **硬件结构 / 机制**      | “汇编程序员”    | **原因**                                             |
| ------------------ | ---------- | -------------------------------------------------- |
| **累加寄存器**          | ❌ 不透明      |                                                    |
| **通用寄存器 **         | ❌ **不透明 ** | 程序员必须在汇编代码里显式写出 `ADD R1, R2`。                      |
| **程序计数器 (PC)**     | ❌ **不透明 ** | 程序员可以通过 `JMP` 等跳转指令直接或间接地修改 PC 的值来改变程序流向。          |
| **状态/标志寄存器 (PSW)** | ❌ **不透明 ** | 程序员需要根据进位、溢出标志（上文提到的 CF、OF）来写条件分支指令（如 `JZ`, `JC`）。 |
| **指令寄存器 (IR)**     | ✅ **透明 **  | 这是 CPU 内部取指令的私有工作，汇编代码无法访问。                        |
| **微程序 / 微指令**      | ✅ **透明 **  | 这是 CPU 设计者写死在芯片里的底层控制逻辑，程序员无法干预。                   |
| **Cache (高速缓存)**   | ✅ **透明 **  | 硬件自动完成主存和 Cache 的替换与映射，程序员的代码里只有主存地址，没有 Cache 地址。  |
| **MAR 和 MDR**      | ✅ **透明 **  | 这是主存与 CPU 交互的内部缓冲寄存器，对指令集架构不可见。                    |

#### 1. 存储器系统 

- **Cache 替换算法与数据调动：** 对**任何**程序员（包括系统程序员）都 **透明✅**。
    
    - _理由：_ Cache 是纯硬件逻辑实现的。不管你是写 Java 还是写汇编，你的代码里只有主存地址，硬件会自动帮你去 Cache 里找，找不到硬件会自动去主存拿。程序员无法用指令干预 Cache 的内部运作。
        
- **虚拟（主存-辅存）数据调动：** 对应用程序员透明，对系统/汇编程序员不透明❌。
    
    - _理由：_ 缺页异常处理、页表维护、页面置换算法，这些都是操作系统（软件）的代码实现的，系统程序员必须亲手写这些代码，怎么可能透明？
        

#### 2. CPU 内部结构

- **透明✅（看不见，不用管）：**
    
    - 指令流水线（Pipeline）内部机制
        
    - 微程序、微指令控制逻辑
        
    - MAR、MDR、IR（指令寄存器）等内部暂存器
        
    - 算术逻辑单元（ALU）的内部加法器实现
        
- **不透明❌（必须可见，要直接操作）：**
    
    - PC（程序计数器）：写跳转指令（JMP）就是在改 PC。
        
    - PSW（状态标志寄存器）：写条件跳转（如“等于则跳转”）依赖 PSW 的标志位。
        
    - 通用寄存器（R0~Rn）：汇编代码里要明确写出把数据存到哪个寄存器。
        

#### 3. 中断与 I/O 系统

- **中断隐指令：** 对**任何**程序员 **透明✅**。
    
    - _理由：_ 中断隐指令（如保存断点、关中断、引出中断服务程序）是硬件自动完成的，不存在对应的机器指令，程序员想管也管不了。
        
- **中断服务程序：** 对应用程序员透明，对**系统程序员不透明❌**。
    
    - _理由：_ 中断服务程序本身就是一段存在主存里的代码，是系统程序员一行一行写出来的。
