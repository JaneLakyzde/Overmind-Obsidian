补码整数表示整数，原码小数表示浮点尾数，移码表示浮点阶数


对于n位定点整数（包含一位符号位），三种编码的表示如下：

| 编码类型 | 最大值         | 取值范围                     | 不同数值个数         |
| ---- | ----------- | ------------------------ | -------------- |
| 原码   | $2^{n-1}-1$ | $-(2^{n-1}-1)到2^{n-1}-1$ | $2^n - 1$（两个0） |
| 反码   | $2^{n-1}-1$ | $-(2^{n-1}-1)到2^{n-1}-1$ | $2^n - 1$（两个0） |
| 补码   | $2^{n-1}-1$ | $-2^{n-1}到 2^{n-1}-1$    | $2^n$（一个0）     |



# 原码
直观的二进制表示。最高位为符号为，0 正 1 负
n 位定点整数


# 反码
反码通常是原码到补码的过渡
- 正数：等于原码
- 负数：符号数不变，数值位按位取反

# 补码
补码是现代计算机中最常用的整数编码方式
- 正数：补码等于原码
- 负数：在反码的基础上加1
	即原码符号为不变，数值取反后 + 1
	$\bar{x} + 1 = (2^n - 1) - x + 1 = 2^n - x$
	
- 补码的数学原理在于，负数与其对应的正数相加等于0
	 负数的补码就是该负数加上模 (256)
    ```−2−2 的补码（8位） = −2+256=254−2+256=254，即 1111 1110```
    
	实现了0的唯一表示，但是注意范围的不对称：负数多一个 -128
	可以将减法统一为加法，简化了ALU的设计

- 注意！-1的补码可以表示为：1.000 0000
- -128 的补码可以表示为：1,000 0000

### 补码的产生逻辑。
假设计算机字长为 $n$ 位，所有的整数运算都在模 $2^n$ 的意义下进行。 
1. 在模 $2^n$ 环中，元素 $B$ 与其加法逆元 $B_{inv}$ （即 $-B$）相加必须等于加法单位元 $0$： $$B + B_{inv} \equiv 0 \pmod{2^n}$$
2. 在常规算术中，满足上述等式的正整数解为： $$B_{inv} = 2^n - B$$
3. 直接计算 $2^n - B$ 依然需要减法，违背了“消除减法”的初衷。我们对 $2^n$ 进行数学拆分： $$B_{inv} = (2^n - 1) - B + 1$$
4. 不难发现，在二进制表示中，$2^n - 1$ 是一个**全为 1 的 $n$ 位数**（例如 8 位下是 `11111111`）。 用全 $1$ 的数减去 $B$，在二进制位操作中，等价于且仅等价于对 $B$ 的每一位进行**按位取反**（NOT 运算，记为 $\sim B$）： $$(2^n - 1) - B \iff \sim B$$
5. 代入上式，得出 $B$ 的加法逆元即为它的补码： $$B_{inv} = \sim B + 1$$
> 因为原码**人为地、提前地**把最高位设成了 1，导致从原码推导补码时，为了保住那个 1，不得不发明出“符号位不变”的蹩脚规则。只要我们抛弃原码，直接从正数求它的加法逆元（相反数），所有位一视同仁地取反加一，逻辑就完美自洽了。

# 移码
- 在补码的基础上，将符号位取反即可

- 特点在于：0 的唯一表示
	并且大小直观，数值越大，其机器数也越大，方便浮点数大小比较

- 注意：1000 0000 原码为-0，补码为-128，移码为0
