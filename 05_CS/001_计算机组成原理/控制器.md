# 硬布线控制器

- 硬布线控制器是通过**逻辑门电路和触发器**构成的复杂树形网络。
	它的基本原理是将控制部件看作产生固定时序控制信号的逻辑电路，其输出的微命令是由指令操作码、时序信号和状态条件决定的组合逻辑函数。
- CU 一般会接受三类信号: 
	1. 译码指令信息
	2. 时钟脉冲
	3. 状态反馈
	一个译码指令信息 + 多个时钟节拍 = 多个微操作控制信号, 共同实现指令操作

- **核心特点：** 纯硬件实现，速度极快（通常没有额外的延迟）。
- **致命弱点：** 结构庞杂，缺乏灵活性。一旦设计完成，如果要增加新的指令或修改原有指令，就必须重新设计和布线全部硬件逻辑。
- 通常用于[[指令系统|RISC]]（精简指令集）架构中。

# 微程序控制器

微程序控制器的核心思想是“存储逻辑”。
	它将机器指令的执行过程分解为一系列基本的微操作，并将产生这些微操作的控制信号（微命令）按特定的格式编成微指令，存放在CPU内部的一个只读存储器（控制存储器）中。
	
	执行机器 = 微程序 = 执行一段微指令 = 执行很多段微命令 = 执行很多段相容微命令 = 一系列微操作
## 基本概念

### 1. 微命令与微操作

- **微命令：** 控制部件向执行部件发出的各种控制信号（相当于“命令”）。构成控制信号序列的==最小单位==
- **微操作：** 执行部件接受微命令后所进行的操作（相当于“执行”）。微操作控制信号 = 微指令译码信号 + 时序信号

### 2. 微指令与微周期

- **微指令：** 在一个微周期内，控制完成一组微操作的微命令的集合。它存储在控制存储器中
	微指令 = 操作控制字端 + 顺序控制字端 = 微操作码字端 + 下址字端
- **微周期：** 从控制存储器中读取一条微指令并执行相应的微操作所需的时间。通常假设为一个时钟周期。

### 3. 主存储器与控制存储器

- **主存储器（Main Memory, MM）：** 在CPU外部，用于存放用户**程序和数据**。由 RAM 和 ROM组成，可通过系统总线访问。
- **控制存储器（Control Memory, CM）：** 在CPU内部（控制器中），专门用于存放**微程序**。由高速ROM构成，对程序员是[[透明性|透明]]的。

### 4. 程序与微程序

- **程序：** 由一系列**机器指令**组成，存放在主存中，用于完成特定的用户任务。
- **微程序：** 由一系列**微指令**组成，存放在控存中。**一条机器指令对应一个微程序**。本质上是机器指令的硬件级解释逻辑
	用于解释和执行机器指令的。机器指令对应微程序的入口地址主要由操作码决定
	完全[[透明性|透明]] 


|**节拍**|**微操作描述 (Micro-op)**|**核心微命令 (Micro-command)**|
|---|---|---|
|**T0**|将指令地址送往存储器地址寄存器|$PC_{out}$ , $MAR_{in}$|
|**T1**|启动存储器读，PC 自动加 1|$Read$ , $PC+1$ (或 $ALU$ 逻辑)|
|**T2**|将从存储器读出的指令送入 IR|$MDR_{out}$ , $IR_{in}$|

## 组成和工作过程

微程序控制器的主要组成部分包括：

1. **控制存储器 (CM)：** 存放所有微程序。
2. **微地址寄存器 (CMAR / $\mu$AR)：** 存放将要读取的微指令在控存中的地址。
3. **微指令寄存器 (CMDR / $\mu$IR)：** 存放从控存中读出的微指令。
4. **微地址形成部件：** 用于产生下一条微指令的地址。
    

**基本工作过程：**

1. 统一取机器指令：根据PC将机器指令取入IR。
    
2. 机器指令译码：根据IR中的操作码，通过微地址形成部件产生该机器指令对应的**微程序入口地址**，并送入CMAR。
    
3. 取微指令：根据CMAR的地址，从CM中读出微指令送入CMDR。
    
4. 执行微指令：CMDR产生微命令控制相关部件，并根据下址字段和条件标志生成下一条微指令的地址。
    
5. 循环往复，直到该微程序结束，再回到第1步取下一条机器指令

## 水平型微指令编码方式
### 1. 直接编码方式

- **别名：** 直接控制方式。
- **原理：** 在微指令的操作控制字段中，**每一位代表一个微命令**。某位为“1”表示发出该微命令，为“0”则不发出。
- **优点：** 简单直观，执行速度快，各个微命令可以高度并行。
- **缺点：** 微指令字长过长，导致控存容量极大（因为控存字长等于微指令字长）。
    
### 2. 字段直接编码方式

- **原理：** 将微指令的操作控制字段划分成若干个子字段，**互斥**的微命令放在同一个字段中，**相容**的微命令放在不同的字段中。每个字段通过译码器译码后发出具体的微命令。
- **考研重点规则：**
    1. 互斥性：每个字段内的微命令必须是互斥的（不能同时出现）。
    2. 留空：每个字段必须留出一个状态表示“不操作”。全0通常用来表示不发出任何命令。
- **优缺点：** 极大地缩短了微指令字长，但增加了硬件（译码器）的开销，且由于需要译码，执行速度相对较慢。

## 地址形成方式

1. **断定方式（直接由微指令的下址字段指出）：** 微指令中专门设置一个下址字段（Next Address），直接给出下一条微指令的地址。这是最基本的方式。
    
2. **根据机器指令的操作码形成：** 机器指令取至IR后，其操作码经过微地址形成部件，直接映射为该指令对应微程序的首地址。
    
3. **增量计数器方式：** 类似PC，$(\text{CMAR}) + 1 \rightarrow \text{CMAR}$。
    
4. **根据状态条件分支：** 结合条件码（如进位、溢出）和微指令中的分支控制字段来修改微地址的某些位。

## 微指令的格式

- **水平型微指令：** 一次能定义并执行多个并行操作。直接编码、字段直接编码等都属于水平型。字长长，微程序短，执行速度快。(胖)
	 操作控制 + 顺序控制
    
- **垂直型微指令：** 格式类似于机器指令，包含操作码和操作数地址。每次只能完成一两个微操作。字长短，微程序长，执行速度慢。(瘦)
	微操作码 + 目的地址 + 源地址
	
	

| **对比维度**   | **水平型微指令 (Horizontal)**               | **垂直型微指令 (Vertical)**              |
| ---------- | ------------------------------------- | ---------------------------------- |
| **基本格式**   | 较长。通常由**多个操作控制字段**和顺序控制字段构成。          | 较短。类似于机器指令，由**微操作码**和微操作数或微地址构成。   |
| **并行执行能力** | **强**。一条微指令可以同时定义并执行多个并行的微操作。         | **弱**。一条微指令通常只能完成一到两个微操作，基本没有并行能力。 |
| **微程序长度**  | **短**。因为一条微指令能干很多事，解释一条机器指令所需的微指令条数少。 | **长**。解释一条机器指令需要很多条微指令串行执行。        |
| **微指令字长**  | **长**。为了容纳多个并行控制信号，字长通常有几十位甚至上百位。     | **短**。通常只有十几位到二十几位。                |
| **执行速度**   | **快**。微程序短，访问控制存储器（CM）的次数少。           | **慢**。微程序长，需要频繁访问控制存储器（CM）取微指令。    |
| **CM容量需求** | 控存字数少，但字长长。通常采用“宽而浅”的存储器结构。           | 控存字数多，但字长短。通常采用“窄而深”的存储器结构。        |
| **与硬件的关系** | 联系紧密。需要熟悉硬件内部的数据通路和逻辑结构。              | 相对独立。屏蔽了底层硬件细节。                    |
| **编写难易度**  | **难**。编写微程序复杂，需要考虑各个微操作在时间上的重叠和冲突。    | **易**。编写方式类似于汇编语言，直观且容易掌握和修改。      |
    
- **混合型微指令：** 结合了水平型和垂直型的优点。

# 硬布线控制器和微程序控制期的对比

| **对比维度**     | **硬布线控制器 (组合逻辑)**    | **微程序控制器 (存储逻辑)**     |
| ------------ | -------------------- | --------------------- |
| **工作原理**     | 综合化、树形逻辑网络产生控制信号     | 将控制信号编译成微指令存放在控存中     |
| **执行速度**     | **快**（主要取决于逻辑电路的延迟）  | **慢**（需要多次访问控制存储器）    |
| **规整性与设计难度** | 结构不规整，设计极其复杂，易出错     | 结构规整，设计较简单            |
| **灵活性与可扩充性** | **差**（修改指令需重新设计全套硬件） | **好**（修改或增加指令只需重写微程序） |
| **应用场合**     | RISC、高速计算机           | CISC、普通计算机            |
| **成本**       | 较高（硬件开销大）            | 较低（随着存储器成本下降而体现优势）    |
