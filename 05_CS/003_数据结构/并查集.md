# 双亲表示法

并查集采用[[05_树|双亲表示法]]，所有结点存于数组，每个元素记录数据和双亲下标。它只关心“谁是谁的父亲”，不关心孩子。

通常用森林实现，每个集合对应一棵树，根结点的特征是其双亲下标指向自己或一个特殊值

```c
#define SIZE 100
int father[SIZE]; // 双亲数组

// 初始化：各自为独立集合
void Initial(int n) {
    for (int i = 0; i < n; i++) {
        father[i] = i; // 每个元素父结点是自己
    }
}
```
*考点：初始化时每个元素父结点指向自己，表示有 n 个独立集合。*

# UNION 操作与优化

**基本思想**：要合并两个集合，只需找到它们各自的根，然后将一个根设为另一个根的子结点。

**核心优化：小树并入大树**
为了避免树退化成单链表，必须将高度或结点数小的树，合并到大的树下。

-   **按秩合并（按高度）**
    用 `rank` 数组记录每棵树高度的上界。把矮树的根指向高树的根。只有当两棵树高度相同时，合并后新高度才会加1。

    ```c
    // rank数组初始化时全为0
    void Union(int a, int b) {
        int rootA = Find(a);
        int rootB = Find(b);
        if (rootA == rootB) return;

        if (rank[rootA] < rank[rootB]) {
            father[rootA] = rootB;
        } else if (rank[rootA] > rank[rootB]) {
            father[rootB] = rootA;
        } else {
            father[rootB] = rootA;
            rank[rootA]++; // 高度相同，并入后根高度+1
        }
    }
    ```

-   **按大小合并（按结点数）**
    用 `size` 数组记录集合元素个数。总是把元素少的集合并入元素多的集合，根结点的 `size` 可以存为负数（如 -size），节省空间。

**优化后树高与查找时间复杂度**：经过此优化，树高可控制在 `O(log n)`，那么查找操作的时间复杂度也是 `O(log n)`。

# FIND

**基本思想**：反复找父结点，直到找到根（父结点等于自身的结点）。

**核心优化：路径压缩**
在查找根结点的过程中，把路径上所有结点直接挂到根结点下。这样下次查找就极快。

```c
int Find(int x) {
    // 递归实现
    if (father[x] != x) {
        father[x] = Find(father[x]);
    }
    return father[x];
}
```
**效果**：`Union` 和 `Find` 操作结合后，单次操作的均摊时间近乎为常数 `O(α(n))`，其中 α 是增长极慢的反阿克曼函数，考研中通常视其为常数级。

# 考点总结

1.  **核心定义**
    *   一种支持**动态维护集合**，并能快速处理**合并**与**查询**的数据结构。
    *   本质是用**双亲表示法**存储的**森林**。

2.  **关键优化**
    *   **Union优化**：小树合并到大树下（按秩或按大小）。
    *   **Find优化**：路径压缩。
    *   **效果**：两者结合后，时间复杂度为近似线性的 `O(m·α(n))`。

3.  **应用场景（重中之重）**
    *   **判断图的连通性**：能否从顶点 A 走到 B。
    *   **检测无向图环**：对每条边，若两端点已属同一集合，则存在环。
    *   **Kruskal 最小生成树算法**：判断添加边是否会形成环。

4.  **易错点警示**
    *   初始状态 n 个元素是 n 个独立集合，父结点指向自己。
    *   **“属于同一集合” ≠ “连通”**。前者是并查集的结果，后者是图本身的性质。
    *   只有连通图，才可能所有顶点同属一个集合。
