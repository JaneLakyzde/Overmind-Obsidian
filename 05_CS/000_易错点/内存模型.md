## 进程虚拟地址空间

- **进程内存空间模型**（Process Memory Space Model），
	更准确地说是**进程虚拟地址空间**（Virtual Address Space, VAS），
	是操作系统为每个运行中的进程提供的一个核心抽象。

它是一个独立的、私有的、从 $0$ 开始的连续地址空间
	（例如，在 32 位系统上为 0 到 $2^{32}-1$）。

## 1.核心特性

1. **隔离性 (Isolation):** 每个进程的 VAS 都是私有的。进程 A 无法直接访问进程 B 的 VAS。这由 CPU 的内存管理单元 (MMU) 硬件强制执行，是现代操作系统的主要保护机制。
    
2. **虚拟性 (Virtualization):** VAS 中的地址是**虚拟地址**（Virtual Addresses）。它们不是物理 RAM 上的真实地址。OS 负责维护**页表 (Page Tables)**，MMU 使用页表将虚拟地址**转换**为**物理地址**（Physical Addresses）。
    
3. **一致性 (Consistency):** 尽管每个进程的 VAS 是私有的，但它们的**内部布局（Layout）遵循由 OS 和可执行文件格式（如 ELF）定义的标准规范**。这使得编译器、链接器和加载器可以按标准方式生成和加载程序。

## 2. 经典内存空间布局

所有进程的 VAS 共享一个通用的高层结构，即分为**用户空间 (User Space)** 和**内核空间 (Kernel Space)**。

 - **用户态：** 进程执行应用程序代码时的状态。CPU 权限受限，不能执行危险指令（如 I/O, 内存管理配置）。
 
 - **内核态：** 进程通过**系统调用 (System Call)**、**中断 (Interrupt)** 或**异常 (Exception)** 进入的状态。CPU 拥有最高权限 (Ring 0)，可以执行所有指令，代表进程访问内核数据和硬件。

- 32-bit 系统的 4GB VAS 通常按 3:1 比例划分（具体边界可配置）：
```
   高地址 (High Address)
+-----------------------+ 0xFFFFFFFF
|                       |
|                       | <-- 约 1GB (e.g., C0000000 - FFFFFFFF)
|    (Kernel Space)     |  * 进程在用户态不可见，不可访问
|                       |  * 映射到物理内存，所有进程共享
+-----------------------+ 0xC0000000 (3GB) --- 用户/内核分界线
|                       |
|    参 数 / 环 境 变 量  |
|                       |
+-----------------------+
|       (Stack)         |  <-- 自动管理，用于函数调用
|          |            |      (向下增长  ↓)
|          v            |
|                       |
|       (Space)         |
|                       |
+-----------------------+
|        (mmap)         |  <-- 动态库 (.so), 共享内存, mmap 文件
|          ^            |      (向上增长  ↑)
|          |            |
+-----------------------+
|        (Heap)         |  <-- 动态分配 (malloc/new)
|          ^            |      (向上增长  ↑)
|          |            |
+-----------------------+ 0x08048000 (e.g., .text start)
|      .bss (BSS)       |  <-- 未初始化数据 (自动清零)
+-----------------------+
|      .data            |  <-- 已初始化数据
+-----------------------+
|      .rodata          |  <-- 只读数据 (常量)
+-----------------------+
|      .text (Code)     |  <-- 可执行指令 (只读, 可共享)
+-----------------------+
|       ...             |  <-- (e.g., 保留区, 捕获 NULL 指针)
+-----------------------+ 0x00000000
   低地址 (Low Address)
```

_(注：64 位系统 VAS 极其庞大 (e.g., $2^{48}$ 字节)，布局原则类似，但地址范围和区域间距要大得多。)_

## 3. 用户空间

这是进程“拥有”的区域，包含其代码和数据。它在可执行文件（如 ELF）中被定义，并在加载时由 OS 映射到内存中。

### 3.1 静态生命周期

程序启动到程序关闭的生命周期中一直存在
	主要包括了[代码区]和[全局区]
	这些段通常在程序加载时（`execve`）从可执行文件映射而来。

#### 代码区
`.text `

- **内容：** 程序的机器指令
- **权限：** **只读+可执行**
    - _只读_ 防止程序意外（或恶意）修改自身代码。
    - _可执行_ 允许 CPU 从此处取指执行。
- **特性：** 可共享。
	如果多个进程运行同一个程序（如 `bash`），
	它们在物理内存中共享同一份 `.text` 副本，节省 RAM

` .rodata`
- **内容：** 程序中定义的常量数据。
- **示例：** `const int x = 10;`，字符串字面量 (`"Hello World"`)。
- **权限：** **只读 (Read-Only)**。任何试图写入此区域的行为都会导致段错误 

#### 数据区
`.data`
- **内容：** [已初始化]的[全局变量]和[静态变量]
    全局变量 是在所有函数外定义的变量, 未初始化的值固定为0, 这点与栈变量不同
	静态变量 就是在栈变量前加一个`static`, 同时限制了访问范围

`.bss`
	Block Started by Symbol 或 Better Save Space
- **内容：** [未初始化]的[全局变量]和[静态变量]（或初始化为 0）。
	- **关键优化：** BSS 段在可执行文件中**不占用空间**（只记录其大小）。
	- **加载过程：** 程序加载器 (Loader) 分配此区域内存，并**自动将其全部清零**。

---

### 3.2 动态生命周期

主要包括[堆]区, `new` 的时候创建, `delete` 的时候销毁, 空间超级大, 取决于电脑配置
注意! 指针地址仍然存放在栈区, 会被自动释放, 而堆中的数据如果没有释放会导致内存泄漏
推荐头文件智能指针 `#include<memory>`

#### 堆区 
`Heap`
- **目的：** 用于**动态内存分配**（Dynamic Memory Allocation）。
	 由程序员手动管理
	 通过 `malloc()` / `free()` 或 `new` / `delete` 进行分配和释放
    
- **问题：** 内存泄漏、内存碎片、悬空指针

#### 内存映射区 
	Memory Mapping Segment / mmap region

- **目的：** 这是现代 OS 中非常重要的区域。用于：
    
    1. 加载**动态链接库 (Shared Libraries)** (如 `.so` 文件)。
    2. **内存映射文件 (Memory-mapped files)**（`mmap` 系统调用）。
    3. **共享内存 (Shared Memory)**（`shmget`）。
    4. 某些大块的动态分配（`malloc` 超过一定阈值时会使用 `mmap` 而非 `brk`）。

### 3.3 自动生命周期
#### 栈
	Stack
- 管理每次函数调用, 会使用栈区的空间, 内存的分配和释放全自动
- **内容：** 每个函数调用都会创建一个**栈帧 (Stack Frame)**，用于存储：
    1. **局部变量**（如 `int a = 10;`）。
    2. **函数参数**
    3. **返回地址**
    4. (一些寄存器的保存，如基址指针 `EBP`)。
        
- **管理：** **自动管理**。由编译器生成指令（`PUSH`, `POP`, `CALL`, `RET`）来自动创建和销毁栈帧。
- **问题：** **栈溢出**。当函数调用过深（如无限递归）或栈上分配的局部变量过大时，会耗尽栈空间，导致程序崩溃。通常 1 ~8 MB 大小
    

### 3.3 命令行参数与环境变量

- **位置：** 位于用户空间的最高地址处（栈的上方）。
- **内容：** OS 在启动进程时（`execve`），会将 `main` 函数的 `argc`, `argv` 以及 `envp`（环境变量）放置在此处。
---

## 4. 内核空间

- **内容：** OS 内核的代码、数据、内核模块、驱动程序, [[PCB]] , 内核[[页表]]
- **映射：** 内核空间在**所有进程**的 VAS 中都是**共享**和**一致**的。
- **访问：** 只能在**内核态 (Kernel Mode)** 下访问。
- **目的：**
    1. **高效的系统调用：** 当进程发起系统调用（如 `read`）时，CPU 切换到内核态，**无需切换页表**（因为内核已映射在 VAS 中），可以直接执行内核代码。
    2. **硬件访问：** 内核代码在此处处理中断和访问硬件。

## 5. 线程：共享与私有

在上述进程内存模型的基础上，我们引入了“线程 (Thread)”。线程是 OS 调度的最小单位，而进程是资源分配的最小单位。

这意味着：**一个进程内的所有线程，共享该进程的绝大部分资源。**

引入线程后，原有的进程内存空间（VAS）按所有权被划分为两类：

1. **线程共享区 (Thread-Shared):** 进程“家底”的大部分，所有线程都能访问。
    
2. **线程私有区 (Thread-Private):** 每个线程“随身”携带的、独占的资源，用于维持其独立的执行流。
    

## 6. 多线程内存布局

当进程创建新线程时（例如调用 `pthread_create`），**最核心的变化**发生了：

**OS (或线程库) 会在该进程 VAS 的“空闲区域”（通常是 `mmap` 区）中，为这个新线程分配一块新的内存，作为它自己的私有栈。**

我们从只有一个栈 (Stack)，变成了有 N+1 个栈（N 为子线程数，1 为主线程栈）。

Plaintext

```
   高地址 (High Address)
+-----------------------+
|      内核空间         | (所有线程共享)
+-----------------------+ 0xC0000000
|      主线程 栈 (Stack)  |  (线程 1 私有)
|          |            |
|          v            |
+-----------------------+
|       (空闲区域)        |
|          ...          |
+-----------------------+
|      线程 3 栈        |  (线程 3 私有)
|          |            |
|          v            |
+-----------------------+
|      线程 2 栈        |  (线程 2 私有)
|          |            |
|          v            |
+-----------------------+
|   内存映射区 (mmap)     | (所有线程共享)
|          ^            |
+-----------------------+
|      堆 (Heap)        | (所有线程共享)
+-----------------------+ 0x08048000
|      .bss (BSS)       | (所有线程共享)
+-----------------------+
|      .data (Data)     | (所有线程共享)
+-----------------------+
|      .text (Code)     | (所有线程共享)
+-----------------------+ 0x00000000
   低地址 (Low Address)
```

_(注意：新栈通常在 `mmap` 区域分配，并设置有“保护页” (Guard Page) 来防止栈溢出后破坏其他数据。)_

## 7. 共享资源 vs 私有资源

这张表是多线程编程的**关键**。

### 7.1 共享资源

|**资源**|**内存区域**|**备注**|
|---|---|---|
|**代码段**|`.text`|所有线程执行相同的代码（函数）。|
|**数据段**|`.data` / `.bss`|**全局变量**和**静态变量**被所有线程共享。|
|**堆内存**|`Heap`|线程 A `malloc` 的内存，线程 B 可以访问（甚至 `free`）。|
|**内存映射区**|`mmap`|动态库 (`.so`)、共享内存、`mmap` 映射的文件。|
|**文件描述符**|内核|线程 A `open` 一个文件，线程 B 可以 `read` 这个文件句柄。|
|**信号处理器**|内核|(大部分) 进程收到信号时，由哪个线程处理比较复杂，但表是共享的。|

由于 .data, .bss 和 Heap 是共享的，这正是多线程“力量”的来源（数据共享高效），也是“危险”的根源（**数据竞争 Race Condition**）。

- 如果两个线程**同时**修改一个全局变量（`g_count++`），就会导致数据不一致。
    
- **必须使用同步机制**（如：**互斥锁 Mutex**、**信号量 Semaphore**）来保护共享数据。
    

### 7.2 私有资源

这些资源是每个线程独有的，OS 必须为每个线程单独分配。

| **资源**           | **内存区域** | **备注**                                                                                         |
| ---------------- | -------- | ---------------------------------------------------------------------------------------------- |
| **栈 (Stack)**    | `Stack`  | **最重要的私有资源**。<br><br>  <br>  <br><br>用于存储该线程的**函数调用**、**局部变量**、**参数**。                         |
| **寄存器**          | CPU      | **Program Counter (PC)**、**Stack Pointer (SP)**、通用寄存器等。<br><br>  <br>  <br><br>这决定了线程“执行到哪里了”。 |
| **线程 ID**        | 内核       | 唯一的线程标识符 (TID)。                                                                                |
| **`errno`**      | TLS      | C 语言的 `errno` 错误码必须是线程私有的，否则线程 A 的错误会覆盖 B 的。                                                   |
| **线程本地存储 (TLS)** | `TLS`    | 一种特殊的内存区域，允许线程拥有“看起来像全局，但实际是私有”的变量。                                                            |
| **调度策略/优先级**     | 内核       | 线程可以有自己的调度优先级。                                                                                 |

**[!] 核心后果：**

- **栈私有**：线程 A 无法（也不应该）访问线程 B 的**局部变量**。
    
- **`errno` 私有**：线程库（如 pthreads）使用**线程本地存储 (Thread-Local Storage, TLS)** 技术来确保 `errno` 等变量对每个线程是唯一的。

## 8. 总结

- **优势 (Why use threads?)**
    
    1. **创建开销小：** 创建线程（`pthread_create`）**远快于**创建进程（`fork`）。因为 OS **不需要**复制整个 VAS 或页表，只需创建一个内核 TCB (Thread Control Block) 和一块新的**栈内存**。
        
    2. **通信高效：** 线程间共享数据**极其高效**。它们访问同一个全局变量（同一块内存地址），无需像进程间通信 (IPC) 那样通过管道、消息队列或内核中转。
        
- **代价 (What's the challenge?)**
    
    1. **同步 (Synchronization)：** 你（程序员）必须**手动**负责保护共享数据（Heap, .data, .bss）。这是多线程编程最复杂的部分。
        
    2. **栈溢出：** 每个线程的栈大小是有限的（通常比主线程小，e.g., 2MB 或 8MB）。如果单个线程递归过深或定义了超大局部数组，会导致该线程的栈溢出。
