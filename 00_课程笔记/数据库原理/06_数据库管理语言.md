# 并发控制

| :--------------- | :-- | :---- | :-- | :------------ |
| Read Uncommitted | 允许  | 允许    | 允许  | 无锁            |

### 并发带来的问题

1. 丢失修改
- **定义**：两个或多个事务并发修改同一数据时，其中一个事务的修改被另一个事务的更新覆盖，导致部分修改丢失。
- **场景**：事务A和事务B同时读取同一数据。事务A修改数据后写回，事务B也修改数据并写回，覆盖了事务A的修改。

2. 脏读
- **定义**：一个事务读取了另一个**未提交事务**修改的数据。如果未提交的事务回滚，读到的数据就是无效的（“脏数据”）。
- **场景**：小明向小红转账。事务A（小明）执行`UPDATE 账户 SET 余额 = 余额 - 100 WHERE 姓名='小红';`（未提交）。事务B（小红）执行`SELECT 余额 FROM 账户 WHERE 姓名='小红';`，看到余额多了100元。结果：事务A回滚（撤销转账），但小红已读到“脏数据”（实际余额未增加）。

3. 不可重复读
- **定义**：在同一事务内，多次读取同一数据，结果不同。因为其他事务在两次读取之间**提交**了修改。
- **场景**：小明查看商品库存。事务A（小明）第一次查询`SELECT 库存 FROM 商品 WHERE 名称='手机';`，库存为10。事务B（商家）执行`UPDATE 商品 SET 库存 = 9 WHERE 名称='手机';`（提交）。事务A再次查询，库存变为9（同一事务内两次读取结果不同）。

4. 幻读
- **定义**：在同一事务内，同样的查询条件返回了**不同数量的行**。因为其他事务插入了符合查询条件的新数据并提交。
- **场景**：小明统计某类商品种类。事务A（小明）第一次查询`SELECT COUNT(*) FROM 商品 WHERE 类别='电子产品';`，结果为5种。事务B（供应商）插入一条新电子产品并提交。事务A再次查询，结果为6种。结果：同一查询条件返回了不同行数（多了1条“幻影”数据）。

5. 锁机制
- **共享锁（S锁）**：允许多个事务同时读取同一数据，但阻止其他事务获取排他锁。示例：`LOCK TABLE Account IN SHARE MODE;`
- **排他锁（X锁）**：只允许一个事务独占数据，其他事务无论是读还是写都无法获取锁，直到排他锁被释放。示例：`LOCK TABLE Account IN EXCLUSIVE MODE;`

### 封锁协议

1. **一级封锁协议**：修改时，必须加X锁，直到结束。
2. **二级封锁协议**：读的时候，加S锁，读取完就放。
3. **三级封锁协议**：读的时候，加S锁，直到事务结束。

- **一级锁协议**：解决丢失修改。
- **二级锁协议**：解决读脏数据。
- **三级锁协议**：解决不可重复读。
- 两段锁协议: 遵守一定是可串行化的, 不遵守的话有可能是也有可能不是
### 可串行化调度
`SERIALIZABLE`
- 可串行化调度:
	一个并发执行的调度，其效果与某个串行调度的效果完全相同。
