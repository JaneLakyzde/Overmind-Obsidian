学习如何**拦截、观察、伪造、操控网络通信**, **MITM（中间人攻击）

## 一、这套内容的主线是什么

1. **通信是分层完成的**：链路层、网络层、传输层各做不同的事。
    
2. **拦截通信有两类能力**：
    
    - 被动观察：监听、抓包、分析流量。
        
    - 主动操控：伪造报文、修改路由、ARP 欺骗、插入/阻断流量。
        
3. **安全问题往往来自“信任了不该信任的信息”**，例如仅凭源 IP、源端口、Cookie、ARP 映射就相信对方。

## 二、最基础的网络交互：连接、发送、监听

模块最开始先让你掌握最基本的主机通信操作：

- **Connect**：主动连接远程主机某个端口。
    
- **Send**：建立连接后发送消息。
    
- **Shutdown**：通过关闭标准输入来结束发送。
    
- **Listen**：本机监听某个端口，等待别的主机连进来。

### 1. `nc` / netcat 是最基本的网络瑞士军刀

课程明确用 `nc` 作为入门工具来建立 TCP 连接、监听端口、测试服务。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. TCP 连接是双向的

一旦连接建立，双方都能收发数据，不只是“客户端发、服务端收”。课程在 Listen 关卡中特别强调：一方负责 listen，另一方负责 connect。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 3. 终端输入是带缓冲的

你在终端里输入内容，不按回车并不会立刻发出去；按回车后，整段输入才会作为数据发送。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 4. “关闭连接”也是协议动作的一部分

有些服务端会等你明确结束输入后才返回结果。课程借此说明：网络程序里，**EOF / half-close / shutdown** 这样的动作也很重要。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

## 三、发现目标：扫描与枚举

后续题目进入“你不知道对方在哪”的场景：

- `Scan 1`：在 `/24` 网段里找目标。
    
- 后面还有更大范围、更强调效率的扫描。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

重点知识点：

### 1. 存活主机发现

课程先用 `ping` 让你理解：扫描的第一步通常不是直接打应用协议，而是先看主机是否在线。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. 脚本化枚举

pwn.college 明确鼓励用 shell loop 做批量扫描，这体现出一个渗透测试常识：  
**会脚本化，才能把简单动作扩展到整个网段。** ([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 3. `nmap` 的效率与策略

课程指出大网段扫描时需要关注扫描速度、并发度、是否做 DNS 解析等参数，说明扫描不是“有工具就行”，而是**在时延、噪声、覆盖率之间做权衡**。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

## 四、被动监听：抓包、流量分析、会话重组

模块中段进入“Monitor 1 / Monitor 2 / Sniffing Cookies”：

- 用 Wireshark 监控流量。
    
- 分析慢速流量。
    
- 从流量中偷取管理员 Cookie。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

核心知识点：

### 1. 抓包是理解通信最直接的方法

课程直接推荐用 **Wireshark** 来观察端口 31337 上的流量。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. 关注“流”而不是单个包

真正的敏感信息常常不是在单个包里一眼看出，而是在一整段 TCP stream 中重组后才明显。课程的监控题和 Cookie 题都体现这一点。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 3. 明文协议天然容易泄露会话凭据

“Sniffing Cookies” 这个练习的核心就是：如果 Cookie 经过可见流量传输，攻击者拿到后就可能直接复用身份。课程还提示可以结合前面 Web 模块的 HTTP 工具使用 Cookie。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 4. 被动监听已经足以造成严重后果

即使你没有“入侵”服务器，只要能看到通信，就可能窃取会话、读取敏感数据、伪装管理员。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

## 五、网络接口与配置：通信为什么有时根本到不了

`Network Configuration` 这一题把重点放在网络接口与 IP 层配置上。课程说明：  
链路层负责收发帧，而 IP 地址决定接口接收哪些三层数据包；接口必须被正确配置并处于工作状态，主机才能通信。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

重点可记成：

### 1. 网卡不只是“有个名字”

接口要有：

- 正确的链路层接入
    
- 正确的 IP 地址
    
- 正确的启用状态
    
- 正确的路由上下文
    

否则报文可能根本不会被主机接受。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. 分层调试思维

排查通信问题时，通常按层看：

- 二层通不通
    
- 三层地址对不对
    
- 四层端口是否开放
    
- 应用层协议是否正常
    

这正是整个模块想培养的思维方式。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

## 六、防火墙与流量控制：通信不只是“能通”，还要“按规则通”

模块专门安排了 Firewall 1/2/3：

- 阻断某端口流量
    
- 只阻断某来源主机
    
- 放行原本被阻断的出站流量([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

核心知识点：

### 1. 防火墙本质是流量筛选器

课程直接指出：防火墙通过检查网络流量并执行规则来控制数据流，常用工具是 `iptables`。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. 规则顺序非常重要

这点很关键。很多新手只记“写规则”，但真正决定行为的 often 是**匹配顺序和优先级**。课程明确提醒可以先查看现有规则再调试。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 3. 控制维度至少包括

- 入站 / 出站
    
- 协议类型
    
- 端口
    
- 来源 IP / 目标 IP
    

这些组合起来，才是现实里的访问控制。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

## 七、拒绝服务（DoS）：让服务不可用也是一种攻击

`Denial of Service 1/2/3` 展示的不是传统“大流量打挂”，而是**利用服务模型的弱点干扰可用性**。其中课程提到不同版本的服务端会为每个连接 fork 新进程，甚至限制会话时长。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

这部分要理解：

### 1. DoS 不一定靠海量带宽

只要能消耗对方的：

- 连接数
    
- 进程数
    
- CPU
    
- 文件描述符
    
- 会话时间窗口
    

就可能让正常用户用不了。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. 服务实现方式会改变攻击面

“每个连接 fork 一个进程”和“每个会话 1 秒限制”就是在说明：  
**应用架构决定了它会怕哪种干扰。** ([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

## 八、从协议栈角度看通信：Ethernet → IP → TCP

模块后半段开始要求你**手工构造协议包**：

- Ethernet：手动发以太网帧
    
- IP：手动发 IP 包
    
- TCP：手动发 TCP 包
    
- TCP Handshake：手动完成三次握手([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

这部分是整套内容最核心的理论基础。

### 1. 封装（encapsulation）

课程强调：数据在网络栈中是逐层封装的。应用数据最终会被包进 TCP/UDP，再包进 IP，再包进 Ethernet。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. Socket 是操作系统提供的抽象

课程指出，普通网络程序使用的是 OS 管理的 socket；操作系统会替你维护状态、处理重传、自动生成下层协议头。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 3. Raw Socket / Scapy 让你越过高层抽象

如果想手工伪造包，就不能只停留在普通 socket。课程说明可以用：

- Python `socket` 模块构造原始套接字
    
- `Scapy` 进行更方便的报文构造、嗅探、伪造和测试([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

### 4. TCP 不只是“发数据”

手工发 TCP 包和手工完成握手这两题说明：

- TCP 有状态
    
- 有序号 `seq`
    
- 有确认号 `ack`
    
- 有各种 flags
    
- 握手建立的是双方对连接状态的同步认知([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

一句话概括：  
**TCP 的安全门槛比 UDP 高，很大一部分原因就是它有连接状态和序列控制。**

## 九、UDP：简单、快，但非常容易被玩坏

模块专门把 UDP 拿出来讲了很多：

- UDP 基本收发
    
- 指定源端口
    
- UDP Spoofing 1/2/3/4([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

这是整个模块最值得记住的一段。

### 1. UDP 没有连接概念

课程明确说：UDP 不像 TCP 那样把多个包天然关联成一个连接。每个数据报基本上是独立的。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. UDP 服务器通常自己维护“会话语义”

因为协议本身不管连接状态，应用程序只能自己记“谁是谁”“谁是可信客户端”“当前会话属于谁”。而这正是安全问题来源。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 3. 源端口是身份判断的一部分

课程在 UDP 2 里专门让你绑定源端口，说明很多程序会把：

- 源 IP
    
- 源端口  
    当成“通信身份”的一部分。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

### 4. UDP 欺骗比 TCP 容易

课程在 UDP Spoofing 4 里直接说了：伪造 UDP 比伪造 TCP 容易，因为 TCP 还要知道序列号等状态，而 UDP 不需要。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 5. 这会带来哪些真实风险

课程给了几个非常实用的安全结论：

- **信任混淆**：把不可信连接当成可信连接。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    
- **重定向/反射/放大**：诱导服务器把数据发到别的地址，可用于 DoS amplification。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    
- **DNS 类漏洞**：课程明确提到，历史上著名 DNS 漏洞的核心之一，就是可伪造响应；后来通过**随机化源端口**来增加猜测难度。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

这部分你可以记成一句非常考试风格的话：  
**UDP 的弱点不只是“不可靠”，更关键是“太容易被伪造、混淆和滥用”。**

## 十、ARP：二层身份欺骗的基础

模块最后还单列了 `ARP`，要求手工发送 ARP 包，告诉远端“某 IP 对应某 MAC 地址”。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

核心点：

### 1. ARP 解决的是 IP → MAC 映射

在局域网中，主机想发给某个 IP，必须先知道对应网卡的 MAC 地址。ARP 就是负责这个解析。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. ARP 天生容易被欺骗

因为 ARP 本身缺少强认证机制，只要主机相信伪造的 ARP 响应，就可能把“某 IP 的 MAC”缓存成攻击者的地址。  
这正是后面 Intercept / Man-in-the-Middle 的基础。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

## 十一、Intercept 与 MITM：真正的“拦截通信”

模块最后两题直接就是：

- **Intercept**：拦截两个远程主机之间的流量
    
- **Man-in-the-Middle**：真正站到中间，转发并控制通信([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

这里的知识点可以总结为：

### 1. 被动拦截

目标是“让我看见本来不该给我看的流量”。  
通常依赖：

- 混杂模式抓包
    
- 网络路径控制
    
- ARP 欺骗 / 路由欺骗等手段([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

### 2. 主动 MITM

目标是“通信还在继续，但已经经过我”。  
这意味着攻击者能：

- 读取内容
    
- 修改内容
    
- 插入内容
    
- 选择性丢包
    
- 重放某些数据([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

### 3. 为什么 MITM 危险

因为它不是“单点漏洞”，而是**对整个会话控制权的争夺**。  
一旦中间人成功，认证前的数据、明文协议、Cookie、弱会话验证都可能沦陷。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

## 十三、你真正应该带走的“总纲”

把整套视频压缩成几句：

### 1. 网络安全很多时候就是“谁相信了什么”

- 相信源地址
    
- 相信源端口
    
- 相信 ARP
    
- 相信 Cookie
    
- 相信看起来像合法响应的包
    

而这些东西很多都可以被伪造或窃取。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 2. TCP 和 UDP 的安全边界差异很大

- TCP：复杂、重状态、难伪造
    
- UDP：简单、快、易伪造、应用更容易自己踩坑([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
    

### 3. 能抓包，就能看见很多“应用层以为别人看不见”的东西

这就是为什么明文通信、未保护的会话标识、弱鉴权都很危险。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))

### 4. MITM 的基础往往不是“高深密码学破解”，而是底层网络控制

ARP、路由、端口、接口、伪造包，这些底层能力才是中间人攻击的现实入口。([pwn.college](https://pwn.college/intro-to-cybersecurity/intercepting-communication/ "pwn.college"))
